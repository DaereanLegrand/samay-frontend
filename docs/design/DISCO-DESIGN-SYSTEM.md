## 1. Brand Pillars

| # | Pillar | Rule |
|---|--------|------|
| P1 | **Black always** | `scaffoldBackgroundColor` is `#000000` in every screen, every sheet, every dialog. No light mode, no gray app background. Gray `#0A0A0A`/`#111111` surfaces are allowed only *under* content as depth (cards, overlays), never as the page background. |
| P2 | **Minimalist** | One idea per screen. Generous black space. No decorative chrome, no gradients in chrome, no rounded pastels, no drop shadows on boxes (flat + hairline only). White core, gray for hierarchy. |
| P3 | **Disco glow accents** | Pink glow is the brand signature — **display titles and brand moments only** (see §3.4 usage rules). Accent colors are always used *with contrast* against black, never for whole-screen fills. When in doubt: **white**. |
| P4 | **Premium editorial** | Mirror of `samay_mvp_spec.md` §1: "luxury streetwear brand meets nightlife app. No rounded pastel. No friendly startup. Sharp, clean, aspirational." Serif display type (Playfair Display) is the editorial voice; Inter is the UI voice. |
| P5 | **Disco, not carnival** | Motion is subtle and fast; the only "breathing" is the glow. Respect `MediaQuery.disableAnimations`/`disableAnimationsOf` (see §6, §7). |

**White-only mode (P2 fallback):** when a screen's accent needs are unclear, render it fully white-on-black (white text, white hairlines, white icons). Accent colors are privileges, not defaults.

**Launcher identity (implemented, U-20):** black `#000000` launcher background (P1), soft `glowPink` halo (P3, the §4.3 glow-stack semantics), bold **white diamond outline + solid `glowPink` inner shard** (the §5.6 VShardIcon motif, sharp per §4.2). Regenerable via `dart run tools/icon_gen.dart` → `assets/icons/app_icon.png` + `app_icon_foreground.png`; android/iOS icon sets generated by `flutter_launcher_icons`.

### 2.2 Signature glow pink

| Token | Hex | Usage | Contrast vs `#000000` |
|---|---|---|---|
| `glowPink` | `#FF2E88` | **The signature.** Display titles with glow, brand accents, selected/highlight states, glow buttons | **6.00:1 — AA** |
| `glowPinkBright` | `#FF5CA8` | Glow halo layers, pressed/hover accent tint | 7.35:1 — AA |
| `glowPinkDeep` | `#C2185B` | Pressed state of pink fills, dark-on-pink text pairing | 3.58:1 — AA-large only |

**Rationale for `#FF2E88`:** a hot pink in the saturated magenta family — the canonical "neon disco" hue (references: the brand CSS uses `--pink`; `#FF2E88` is the middle of the classic hot-pink range). Computed relative luminance `L = 0.250` gives **6.00:1 on black**, exceeding WCAG 2.2 AA for normal text (4.5:1) and approaching AAA (7:1). Alternatives considered: `#E91E63` (Material pink, 4.83:1 — passes but muddier, reads more "Material" than disco), `#FF4D9E` (6.81:1 — softer; reserved as a lighter tint family, not the signature). `#FF2E88` is the *brightest* hot pink that still passes AA at normal size — the most "glow" the brand can legally afford.

### 2.4 Muted-text rule (important)

`muted #666666` on black is **3.66:1** — it fails WCAG 1.4.3 for normal-size text (needs 4.5:1). It is legal only for:
- Placeholder/hint text inside inputs **that is never the only source of meaning** (the `labelText`/`hintText` must be re-declared on the field itself, which is white text), or
- Disabled controls (inactive UI components are exempt per WCAG 1.4.3 "Incidental"), or
- Text ≥ 24px (or ≥ 18.5px bold).

Any *informational* text below those sizes must use `mutedStrong #999999` (7.37:1) or white. `#666666` remains the correct **icon** color for unselected bottom-nav items (non-text contrast 3:1 — 3.66:1 passes).

**Tab labels are informational text — never `muted`.** Unselected `TabBar` labels must resolve `mutedStrong` (7.37:1) or the theme default AA color (U-26 fixed the two sites that overrode to `muted`: `shard_ledger_screen`, `cosmetics_shop_screen`). The `tabBarTheme` keeps `unselectedLabelColor`/`labelStyle` at the defaults for this reason (§5.4). **Justified `muted` usages** (U-26 audit table): input/dropdown hints (placeholder exemption), disabled controls (VButton/TextButton disabled, status readouts, locked CTAs/prices), and non-text UI icons (nav icons 3.66:1 ≥ 3:1 — 1.4.11).

### 2.5 Contrast-first usage rules

1. **Accent = text/icon on black, or black text on accent fill.** All accents ≥ 4.5:1 as *text on black*, so accent text is always legal at normal size. On accent *fills*, use black text (pink fill + black text = 6.00:1).
2. **Never white text on a pink/violet fill** — white-on-`#FF2E88` is 3.50:1, failing 1.4.3. (Exception: `glowPinkDeep` fill with white text = 5.87:1, allowed for dark-red pressed states.)
3. **Never use an accent where white suffices.** Accent budget: max ~10% of any screen's pixels; glow titles count as one accent zone.
4. **Never pair two accents** as foreground+background (e.g., violet text on cyan fill) — luminance math is not predictable; use accent + black/white only.
5. **Color is never the only signal** — every accent-coded state (online, VIP, rank, shard balance) also carries a text label, icon, or position change (WCAG 1.4.1 Use of Color).
6. **`glowPinkDeep` and any accent at opacity < 1** may only be used decoratively (glow halos, pressed scrims) — never as the sole text color. The `danger` alias is a *fill* alias (`glowPinkDeep` is AA-large-only as text); the `error` alias is the *text* alias (`glowPink`, 6.00:1) — see §2.6 (U-09 decision, applied in settings/delete-account/public-profile).

### 3.4 Glow text style spec (the signature)

Rendered via Flutter `TextStyle.shadows` (equivalent to the user's CSS `text-shadow: 0 0 0.35em/0.7em/1em var(--pink)`). In Flutter, `em` is relative to font size; `Shadow.blurRadius` is in logical px. **Canonical stacks** (implemented identically in `AppTypography.fancyTitle`, `VGlowText`, and `VBreathingGlow` — the three-way parity is test-pinned, U-06/U-18):

| Variant | Shadows (blurRadius = f(fontSize)) | Use |
|---|---|---|
| `glow-strong` | 3 layers: `glowPink` α0.9 · `fontSize×0.35` · α0.5 at `fontSize×0.7` · α0.25 at `fontSize×1.0` | Display titles ≥ 32px (welcome wordmark, auth headers) |
| `glow-soft` | 2 layers: `glowPink` α0.6 · `fontSize×0.3` · α0.25 at `fontSize×0.6` | Headlines 28px (event titles, podium) |
| `glow-hairline` | 1 layer: `glowPink` α0.35 · `fontSize×0.25` | Small brand accents, icon halos (`VButton.glowAccent` outlined label) |

**Implemented API:** `AppTypography.fancyTitle(TextStyle base, {bool soft})` is the canonical helper (U-02); the theme roles have the glow baked in (display roles glow-strong, `headlineLarge` glow-soft — `AppTypography.textTheme`, U-02); `VGlowText` is the widget form (U-06, const-constructible, any token color); `VBreathingGlow` adds the §6.2 ambient breathing (U-18). **Legibility contract:** the text fill is ALWAYS full-opacity (never blur-only text, never translucent glyphs) — the shadow is strictly *behind* the glyphs (Flutter shadows render behind the fill). Per WCAG 1.4.3, a wide halo counts as *background* for contrast evaluation, so the fill itself carries the ratio — `glowPink` fill on black = 6.00:1 (AA). See §7.4 for the animation amplitude floor.

### 6.2 Disco-glow breathing animation (the one allowed ambient motion)

## 7. Accessibility Rules

U-26 ran the audit (per-SC evidence: 1.4.3, 1.4.4, 1.4.11, 1.4.1, 2.1.1, 2.3.3, 2.4.3, 2.4.7, 3.2.2, 4.1.2) and shipped `test/accessibility/a11y_test.dart` (14 tests). The token table is the contrast contract (U-01 verified every ratio at tolerance 0.02).

### 7.1 Contrast minimums (WCAG 2.2)

- **Text:** ≥ **4.5:1** normal, ≥ **3:1** large (≥24px or ≥18.5px bold). Verified values in §2 tables (computed with the WCAG relative-luminance formula: `L = 0.2126R + 0.7152G + 0.0722B` over linearized sRGB, ratio `(L1+0.05)/(L2+0.05)`; source: W3C Understanding SC 1.4.3; implemented as `AppColors.contrastRatio`, U-01).
- **Non-text (1.4.11):** ≥ **3:1** against adjacent colors for UI component boundaries and state indicators.
- **Audit evidence (U-26):** the only two informational-text `muted` usages (unselected TabBar labels) fixed → `mutedStrong`; every remaining `muted` usage is a documented 1.4.3 exemption (see §2.4). All other contrast decisions (badge 21:1, podium ≥6.68:1, banner white-on-glowPinkDeep 5.87:1, gold shard 13.71:1 non-text, glowPink error 6.00:1) were pre-verified per-screen in the U-23..U-25 ledgers.

### 7.2 Hairline boundaries (1.4.11) — the one deliberate exception

`#1A1A1A` card borders (1.21:1) fail the 3:1 non-text rule **if** the border is the only indicator of the interactive region. Rule: any tappable surface must also carry a text/icon/chevron with ≥4.5:1, and any *state* (selected, focused, error) must be signaled with white or an accent line ≥3:1 — not the hairline alone. Focus indicator: 2px white outline. **Avatar rings are `border #333333`, not `hairline`** (§2.1, U-09 spelling) — the initials carry the text contrast.

### 7.3 Text scaling & responsive layout (U-19 — the 1.4.4 gate)

- All type uses the app `textScaler` (never `textScaleFactor` fixed); `MediaQuery.textScalerOf(context)`.
- No fixed-height text containers; buttons/inputs grow; `maxLines` + ellipsis only on single-line labels.
- `AppSpacing.scale()` for responsive spacing (finding UI-09 — consumer: feed carousel/chip-row heights, §4.1).
- **Scroll-safe body templates (implemented, U-19):**
  - **Pattern A** (text/VInput-only columns — the OTP template, U-07): `LayoutBuilder → SingleChildScrollView → ConstrainedBox(minHeight) → IntrinsicHeight → Column(Spacer)` — pins the CTA when the content fits, scrolls when it doesn't. Applied to login, signup, age-gate, profile-setup, delete-account, banned, welcome, ~~coming-soon~~ (+ OTP/forgot-password born with it).

  > **DEPARTURE (2026-08-13):** VComingSoonScreen deleted — see §5.7 note.
  - **Pattern B** (`CustomScrollView → SliverFillRemaining(hasScrollBody: false)`) for **tile-like children** — `ListTile`'s intrinsic height is smaller than its laid-out height when the subtitle wraps, so the IntrinsicHeight pass under-measures and overflows even inside a scroll view (U-19 MISTAKE 1). privacy_terms uses pattern B with custom `_ConsentRow` (checkbox + text, intrinsic-exact).
  - **Bounded-scroll hero** (group_detail): the header may scroll within `bodyHeight − _minTabArea(120)` so the TabBarView is never crushed (U-19).
  - **Rows:** `Wrap` for badge/button rows that overflow at 1.5× (my_groups, group_detail hero); `Flexible` for shards text.
  - **CTAs:** full-width `ConstrainedBox(maxWidth: 320)` (the 200px fixed family was eliminated — U-19).
- **Test gate:** `test/features/responsive_test.dart` — 18 screens at 1.5× text scale on 320×568 (Ahem font, harsher than any device) asserting zero `RenderFlex` overflows.
- **No-op controls render disabled (U-26, 2.1.1/4.1.2):** a control that looks enabled but does nothing is a violation — status readouts (public-profile 'Bloqueado'/'Amigos'), placeholder rows (settings 'Notificaciones'/'Privacidad'), and 'Cambiar contraseña' all render `onPressed: null`/`ListTile(enabled: false)` → `muted` (§5.1) and lose the chevron affordance.

### 7.4 Glow legibility

- Halo **behind** text is fine (counts as background per WCAG note 5 on 1.4.3); **blur-only text is not** — glyph fill stays 100% opaque `glowPink`/white.
- Breathing amplitude floor α0.75 keeps effective contrast ≥4.75:1 (§6.2).
- Under reduced motion, glow is static (still legal — it is a background halo).

### 7.5 Reduced motion & sensitive users

- `MediaQuery.disableAnimationsOf(context)` gates every ambient animation: `VBreathingGlow` (static α1.0), `VStatusDot` (static α1.0), `VTabFade` (static), `VShimmer` (static blocks, zero tickers), and the §6.3 table's entries. Static fallbacks defined per component.
- No flashing, no strobing, no hue rotation — the disco look is *static color + slow breathing*, safe for photosensitivity (no 3Hz+ flicker anywhere). 2.3.3 evidence: the U-18 widget suites pin `transientCallbackCount == 0` under `disableAnimations`.
- **App-level evidence (U-29):** the UI smoke's ~~coming-soon~~ reduced-motion stop flips `TestPlatformDispatcher.accessibilityFeaturesTestValue = FakeAccessibilityFeatures(disableAnimations: true)` for the whole app → `transientCallbackCount == 0` + shadows at the full α1.0 soft stack. Reusable technique for any future §7.5 verification.

> **DEPARTURE (2026-08-13):** VComingSoonScreen deleted — see §5.7 note.

### 7.6 Color-blindness & semantics

- Pink/violet/gold/cyan are distinguished by luminance (all ≥4.5 vs black) — never by hue alone; every accent state has a text/icon/position companion (1.4.1).
- **Semantics (4.1.2, U-26):** hidden shell nav labels stay announced (SDK `Visibility.maintain` keeps `maintainSemantics: true` — pinned "Feed · Pestaña 1 de 5"); icon-only buttons carry tooltips (settings gear, overflow menus — `commonMoreOptions`); `VShardIcon` is `ExcludeSemantics` (decorative, §5.6); badges expose their uppercase labels; chat undecryptable placeholder announces its label; focus order pinned by a keyboard-tab test (login email → password → forgot → sign-in).

### Extending the system (refactorability — future features)

1. **New color:** add hex + verified ratio to `app_colors.dart`; if it must appear in `Theme.of`, add it to `SamayThemeExtension` (U-04) with `copyWith`/`lerp`; register in `extensions:`; add a row to §2 with the computed contrast; never invent ad-hoc `Color(0x…)` in features.
2. **New text role:** extend `app_typography.dart`; default text roles map onto the §3.3 table; Playfair additions must be approved by this doc's rules (§3.2 exhaustive list) — add to the list, not beside it.
3. **New component:** compose from existing tokens (spacing/radius/durations) + shared widgets (§9); no new shadow stacks beyond §4.3; ship widget test in `test/widgets/` + integration case in `integration_test/` (U-29 pattern).
4. **New feature screen:** follow §1 pillars first (black bg, white core), then apply the relevant component specs; restyle checklist = §§2.5, 5, 7.1; make it scroll-safe per §7.3 (pattern A/B); name its loading state per §5.8 (skeleton vs `VLoadingView`).
5. **Future global change:** touch tokens only — screens must not hardcode design values (the I-16/M-24 token migration enforces this).
6. **Pushed routes with typed extras:** any new route that pushes a typed extra must keep the `RouteExtraCodec` pattern (U-29 BUG 1): go_router JSON-serializes pushed-page extras on every `refreshListenable` re-parse, and non-JSON extras silently decode as null — the codec (tagged maps + `fromObject` factories + value equality) is what keeps the pushed screens alive across auth emissions. See `lib/core/router/route_extras.dart`.
