## 2. What was built

### 2.1 Contrast fixes (§2.4 — the only two text usages of `muted` in the app)

| Site | Before | After | Why |
|---|---|---|---|
| `shard_ledger_screen.dart` TabBar `unselectedLabelColor` | `AppColors.muted` (3.66:1) | `AppColors.mutedStrong` (7.37:1) | Tab labels are informational text at 12px — §2.4 violation; the theme's own `tabBarTheme` comment documents the ban. |
| `cosmetics_shop_screen.dart` TabBar `unselectedLabelColor` | `AppColors.muted` | `AppColors.mutedStrong` | Same. |

### 2.2 Semantic labels (4.1.2)

1. **`profile_screen.dart`** — the settings gear `IconButton` gains `tooltip: l10n.profileSettingsTitle` ('Configuración') — its accessibility name.
2. **`public_profile_screen.dart`** — the AppBar `PopupMenuButton` gains `tooltip: l10n.commonMoreOptions` ('Más opciones').
3. **`group_detail_screen.dart`** — the frozen-marker `PopupMenuButton` gains the same tooltip.
4. **`v_shard_icon.dart`** — the gold diamond is wrapped in `ExcludeSemantics`: decorative in every usage (the adjacent count text is the meaning); explicit intent, no redundant node (1.4.1).
5. New ARB key `commonMoreOptions` ('Más opciones' / 'More options') in `app_es.arb` + `app_en.arb` (+ `flutter gen-l10n` regenerated the three `app_localizations*` files).

### 2.3 No-op controls → disabled rendering (U-23 F3/F4; WCAG 2.1.1/4.1.2 + Flutter's own "active interactions" checklist)

Decision per control — **disabled** (not "próximamente semantics"): §5.1 defines the disabled treatment (drop to `muted`, inactive = contrast-exempt), and `Semantics(enabled: false)` is the exact 4.1.2 state a screen reader needs. The search-screen status labels were already `onPressed: null` (disabled) — verified, untouched.

| Control | Fix |
|---|---|
| `public_profile_screen.dart` — 'Bloqueado' / 'Amigos' / 'Solicitado' (outgoing pending) status readouts | `VButton.emphasized(onPressed: null)` (were `onPressed: () {}`). The incoming-pending 'Aceptar solicitud' and the 'Agregar amigo' actions stay live. |
| `settings_screen.dart` — 'Notificaciones' + 'Privacidad' placeholder rows | `_SettingsTile` gains `enabled` (default true); the two placeholders pass `enabled: false` → `ListTile(enabled: false)` (disabled semantics + theme disabled color ≈ `muted` §5.1) and the chevron affordance is hidden (a disabled row must not advertise navigation). |
| `edit_profile_screen.dart` — 'Cambiar contraseña' | `TextButton(onPressed: null)` (was `() {}`) → theme `disabledForegroundColor: muted` (§5.1). |

### 2.4 Empty-string initials guards (U-24 F3 / U-25 F5 family)

`substring(0, 1)` on a non-null **empty** username is a latent `RangeError` (providers never produce it today, but a defensive guard costs nothing). Guarded to `'?'` (or `'U'` on the public profile, matching its existing fallback) at all 9 sites: `friends_list_screen`, `search_screen`, `blocked_users_screen`, `invite_screen`, `public_profile_screen`, `group_detail_screen` (`_ContributorTile` + `_MemberTile`), `event_detail_screen` (`_PromotorAvatar`), `party_finder_screen` (`_MatchAvatar`).

### 2.5 The semantic test suite — `test/accessibility/a11y_test.dart` (NEW, 14 tests)

Pumps key screens **with semantics enabled** (`tester.ensureSemantics`) on the real `SamayTheme.dark` + es l10n + provider stubs mirroring real Supabase shapes, and asserts the 4.1.2/1.4.1/2.4.3 contract:

- **1.4.3 group** — both TabBars' `unselectedLabelColor` resolves `mutedStrong` (RED before the fix).
- **4.1.2 shell group** — the 5 nav items are announced with their localized labels under the hidden-label theme (framework appends "Pestaña N de 5" — asserted via `RegExp('^label')`), and the tiles carry `isButton` + `isSelected` flags (deduped `SemanticsNode`s; the active Feed tab selected, others not).
- **4.1.2 icon-only group** — the settings gear's semantics `tooltip` = 'Configuración'; the overflow menu's = 'Más opciones' (RED before the fixes; tooltips surface in the semantics `tooltip` field, which VoiceOver/TalkBack announce).
- **4.1.2 disabled group** — 'Bloqueado' and 'Amigos' public-profile buttons, the settings Notificaciones/Privacidad rows and 'Cambiar contraseña' all report `isEnabled = Tristate.isFalse` (RED before the fixes; flag read via the modern `flagsCollection` API — `SemanticsNode.hasFlag` is deprecated in 3.44).
- **1.4.1 group** — `VShardIcon` contributes no label while the adjacent '42 shards' text is announced; `VBadge`/`RankBadge` expose their uppercase labels; the chat undecryptable bubble announces 'Mensaje no descifrable'.
- **2.4.3 group** — login focus lands email → password → forgot-password → sign-in on hardware Tab (asserted via `FocusManager.primaryFocus`).
- The suite's doc comment **references** the 1.4.4 gate (`test/features/responsive_test.dart`, U-19) and the 2.3.3 gate (U-18's `v_breathing_glow`/`v_status_dot`/`v_tab_fade`/`v_shimmer` suites) instead of duplicating them.

## 8. MISTAKE blocks

- **MISTAKE (test finder semantics):** `find.bySemanticsLabel('Feed')` found nothing — the nav tile nodes carry the merged label "Feed\nPestaña 1 de 5" (the framework appends the localized tab-index label). Fixed with `RegExp('^$label')` + a dedupe of merged `SemanticsNode`s for the tile-flag assertions.
- **MISTAKE (tooltip ≠ label):** I asserted icon-button names via `find.bySemanticsLabel` — but IconButton/PopupMenuButton tooltips surface in the semantics **`tooltip` field**, not `label`. Fixed to assert `getSemanticsData().tooltip`.
- **MISTAKE (SemanticsHandle lifecycle):** `addTearDown(handle.dispose)` runs AFTER the end-of-test handle verification → "A SemanticsHandle was active at the end of the test". Fixed: explicit `_disposeSemantics()` at the end of each test.
- **MISTAKE (missing 4th tab keypress):** the focus test evaluated the CTA ancestor before sending the 4th Tab — probe-verified the real order was correct and the test was wrong.
- **MISTAKE (deprecated API):** `SemanticsNode.hasFlag` is deprecated in 3.44 → the modern `flagsCollection` reads (`Tristate.isFalse` for disabled); caught by `dart analyze` and fixed with helper predicates.
- **MISTAKE (in-loop handle disposal):** the blocked/accepted loop disposed the semantics handle inside the loop → the second iteration's `getSemantics` failed on an empty finder. Split into two tests (also cleaner).
- **MISTAKE (allowlist line drift, caught by the campaign's own guard):** the U-26 comment block + `dart format` shifted the U-21 spinner allowlist `edit_profile_screen.dart:202 → :208` — same class of slip as U-23/U-24/U-25; fixed the allowlist entry, re-ran 27/27.

## 9. Decisions made and why

- **Disabled over "próximamente semantics" for no-op controls.** §5.1 already defines the disabled treatment (`muted`, contrast-exempt); `Semantics(enabled: false)` is the exact 4.1.2 state; Flutter's accessibility checklist explicitly demands non-no-op buttons. The settings rows additionally lose their chevron — the "navigates" affordance must not advertise a dead row.
- **`ExcludeSemantics` over `semanticLabel('shards')` for VShardIcon.** The diamond repeats a number the text already announces ("120 shards"); a labeled icon would double-announce. Every usage is decorative by this reading (audited all 8 sites).
- **Tooltips as the icon-button names.** The gear/menu overflow buttons are icon-only by design (minimalist §1); a visible text label would violate the aesthetic contract. Tooltips are the standard Material mechanism and surface in semantics.
- **Nav labels: verified, not changed.** The hidden-label theme is the brand call (U-04); the SDK's `Visibility.maintain(maintainSemantics: true)` keeps the names accessible — pinned rather than forcing labels visible.
- **No gold-plating:** the focus audit found no gaps (default Material rings/overlays + natural traversal + dialog first-focusable); the `muted` hint/icon/disabled usages are documented exemptions, not violations — the §2.4 contract only governs informational text.
