## Deviations from the report (each justified)

1. **R19 implementation — `AnimatedSwitcher` → `_ShellTabFade` fade-in.** The report offered "AnimatedSwitcher/FadeTransition". The switcher was tried first (TDD: tests written against it, RED → implementation → **the suite caught a real crash**: "Duplicate GlobalKey detected … KeyedSubtree-[<0>]" — AnimatedSwitcher keeps the outgoing tab in the tree during the transition while the go_router nested Navigator reparents its GlobalKey'd route entries into the incoming subtree; two live Navigators collide). The fade-**in** (`_ShellTabFade`, keyed on `currentIndex`) is Juega's exact semantics (`child.animate().fadeIn(...)` — the old tab is disposed immediately) and the report's own placement words ("keyed on currentIndex, duration SamayDurations.fast, easeOutCubic; skip when disableAnimations") hold verbatim. This is a *bug-proofing* deviation, not a scope cut: the fade still exists, still 150ms, still reduced-motion-gated.
2. **R20 "family providers" read as "the providers in the three listed files" — all 12 got the guard**, not just the tab-screen families: the report's target list is the three provider files wholesale and its test impact is "+1 per provider". The family notifiers' `refresh()` is uncalled in lib/ (screens use `ref.invalidate`) but the guard is harmless there and keeps the contract uniform. The alternative branch the report offered ("or rely on Riverpod keepAlive where already present") was NOT taken: the root (non-autoDispose) providers already keep state across tab switches, but the *feel* fix the report names is the refresh-path throttle, and the 15s guard is what its tests specify.
3. **R20 test fallout beyond the estimate:** the report's "+1 per provider" did not count the 12 existing tests that pin "`refresh()` re-runs build" (the SM-09 contract tests ×7 + U-16's R13 drag tests ×5). They break under a real 15s window (refresh within 15s legitimately skips). Repointed via the established subclass pattern (`refreshThrottle => Duration.zero` in the counting/stub notifiers) — behavior contracts unchanged. Also: `markFetched()` goes at the END of build (success only), so error-retry is never throttled — the report's "must not mask" applies to actions AND errors.
4. **R18 derived provider, not inline watching:** the report's "Watch a lightweight 'pending counts' provider (friendRequests + groupInvites lengths — both already exist)" is implemented as `pendingCountsProvider` in `main_shell.dart` (Provider<int> watching the two root providers — matching Juega's count formula `isReceived + groupInvites`). This keeps the shell a single-watch consumer and makes the count testable at one seam.
5. **No l10n keys needed** (the badge is a number; the fade is chrome) — R18-R21 required zero ARB edits.

## MISTAKE blocks

- **MISTAKE (caught by my own tests — see deviation 1):** the first R19 implementation used `AnimatedSwitcher`; the router-tap tests (pre-existing, green for 8 prior agents) went RED with "Duplicate GlobalKey" — go_router's shell child is a Navigator whose route entries carry GlobalKeys, and a cross-fade keeps two of them alive. Fixed with the fade-in design; the failure is documented in the widget's doc comment so nobody reintroduces a switcher.
- **MISTAKE (test-design bug at RED time):** my first R19 test asserted `tester.widget<AnimatedSwitcher>(find.byType(...))` — with the fade-in design that finder is meaningless (and ambiguous if the framework ever mounts its own). Rewritten as behavioral pins: fade keyed on the tab index, opacity 0 at switch → 1.0 at exactly `SamayDurations.fast`, absent under `disableAnimations`.

## Issues found (reported, not touched)

1. **AnimatedSwitcher-vs-Navigator (see deviation 1):** any future "cross-fade" around the go_router shell child will hit the duplicate-GlobalKey crash — the shell's child is a live Navigator. Fade-ins only (documented in `_ShellTabFade`'s doc comment).
2. **U-18 handoff:** `_ShellTabFade` is shell-private by design; U-18 owns `SamayDurations` + the reduced-motion contract and may promote a shared fade-in widget if other surfaces want the same tab-switch feel.
3. **U-30 handoff:** `pendingCountsProvider` + the shell badge (R18) and the `ThrottledRefresh` pattern (R20) are worth promoting into DISCO §5 (badge on tab icons) — currently documented in this ledger + widget docs only.
4. **Pre-existing (U-13 §8, still open):** `group_detail_screen._getMemberLimit` hardcodes `'14'` (I-46); friends-list `@username` double render (U-16 decision point, left as-is).
5. **R20 behavior note (intended):** pull-to-refresh on the groups/profile/friends surfaces now *silently* no-ops within 15s of the last successful fetch (Juega's behavior). If a future product decision wants a "force refresh" affordance, the notifier's `shouldRefetch()` gate is the single seam to bypass.
6. **Report misses absorbed:** R20's test impact did not include the 12 existing refresh-contract tests (deviation 3); R19's did not include the AnimatedSwitcher hazard (deviation 1).
