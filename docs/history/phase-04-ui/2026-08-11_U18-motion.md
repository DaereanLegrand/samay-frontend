## The one real design problem: `repeat()` vs `pumpAndSettle()`

A hard `AnimationController.repeat()` schedules frames forever → **every** `pumpAndSettle`-
based widget test that mounts a brand screen (welcome, feed, coming-soon, OTP, banned,
friends list) hangs (10-min timeout each — 40+ tests). The shimmer dodges this only by never
being settled over. The U-18 engine solves it for ALL ambient motion:

- **Idle-safe cycle:** each cycle = 1.5s easeInOut up + 1.5s easeInOut down (`glowBreath`
  3000ms alternate, exactly the doc's loop) + a **300ms static settle** at the low point
  (`motionCycleRest`), then a periodic timer restarts the cycle (period ≈3.3s). Widget tests
  land deterministically during the pause; `pumpAndSettle` settles at the first idle frame.
- **`isAnimating` guard:** a late timer tick (jank, backgrounded frames) is a no-op instead of
  a mid-cycle jump.
- Reduced motion → controller stopped at value 1.0 (static full-α stack / full-α dot — the
  §6.2/§6.3 fallbacks); re-enabling resumes the cycle (tested for both widgets).

## MISTAKE blocks

- **MISTAKE 1 (my own test caught it):** the first dot test asserted the idle window with a
  single `pump(1.8s)` — but the engine's reverse ramp only starts ticking at the frame AFTER
  the forward completes, and the `_cyclePeriod` was written as `liveDotPulse + rest` (1.8s)
  instead of `2 × liveDotPulse + rest` (3.3s) — the periodic timer fired mid-cycle. Fixed the
  period and the test pumps; the `isAnimating` guard now absorbs late ticks. The lesson:
  jump-pumps don't map to frame-continuous time — assert settle via a real `pumpAndSettle()`.
- **MISTAKE 2 (analyzer):** `VBreathingGlow.style` was typed `TextStyle` but the theme roles
  (`Theme.of(context).textTheme.displayMedium`) are `TextStyle?` — made it nullable with a
  const fallback (VGlowText's non-null type would have forced call-site `!`s).
- **MISTAKE 3 (test trap, documented for future agents):** the NAV-08 "no slide wrapper"
  assertion initially matched ANY `SlideTransition`/`ScaleTransition` under the shell
  Navigator — but (a) the ROOT navigator's shell-page transition wraps the whole shell
  (above the shell Navigator) and (b) Scaffold's own `_FloatingActionButtonTransition`
  machinery uses ScaleTransitions inside every page. The precise pin: wrappers that are
  BOTH ancestors of the incoming tab screen AND descendants of the shell Navigator —
  exactly the tab page-transition layer, empty under NoTransitionPage.

## Decisions made and why

- **Breathing scope = the mission's named list + §6.2's "auth headers".** The doc's §6.2
  scope sentence names "welcome wordmark, auth headers"; the mission names welcome / feed /
  coming-soon / OTP / banned. The remaining §3.2 auth headers (signup_contact, age_gate,
  privacy_terms) were left OUT of this pass (not in the mission's list or lock set) — flagged
  for U-30/next agents as a 1-line-per-screen follow-up.
- **No button scale — the doc wins over the user's CSS.** §5.1/§6.1 explicitly ban scale;
  the α0.1 overlay IS the press effect ("minimal", per the mission's 'no cartoon animations'
  reading). Pinned so a future agent can't silently add a bounce.
- **NoTransitionPage, not a global fade-through.** NAV-08's fix is tab-scoped; the doc's §6.1
  "fade-through page transitions" for pushed routes is a separate surface (the current
  MaterialPage push is out of this mission's scope — flagged for U-30).
- **`VBreathingGlow` mirrors `VGlowText`'s API + parity test** instead of touching U-06's
  widget: the §3.4 stack lives in both, byte-parity pinned at the α1.0 peak by a test (the
  same pattern U-06 used vs `AppTypography.fancyTitle`).
- **Reduced-motion static = full α1.0** (not the α0.75 floor): §6.2 says "shadows fixed at
  α1.0" — the canonical stack, byte-identical to the pre-U-18 rendering. Tests pin this.
