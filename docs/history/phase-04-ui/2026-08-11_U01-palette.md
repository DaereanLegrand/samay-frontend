## What was built

U-01 is the finalization review pass over the I-16/I-17 palette (the campaign
moved on without it). The palette itself was audited **hex-by-hex against
§2 and found fully compliant** — no token values were changed. The pass added:

1. **Semantic aliases** in `lib/core/design_tokens/app_colors.dart` — 8 role
   names + a `semantic` map, each resolving to a **canonical §2 token**
   (zero invented hexes, design doc §8.1 honored — these are role names for
   the doc's *usage* column, not new colors):
   | Alias | Resolves to | Doc anchor |
   |---|---|---|
   | `statusVip` | `discoViolet` | §2.3 VIP/subscription tier |
   | `statusOnline` | `discoCyan` | §2.3 live/online indicators |
   | `statusLive` | `discoCyan` | §2.3 realtime dots |
   | `currencyShards` | `discoGold` | §2.3/§5.6 shards currency |
   | `success` | `discoCyan` | §2.3 role resolution (no literal "success" row exists; cyan = the doc's bright-positive token, 13.65:1) |
   | `error` | `glowPink` | §5.2 error *text* (6.00:1 AA; never raw red) |
   | `errorFill` | `glowPinkDeep` | §5.2 error *fill* (white text 5.87:1) |
   | `danger` | `glowPinkDeep` | §5.1 pressed/§5.2 destructive family |
2. **Lerp correctness verified (finding):** `SamayThemeExtension.lerp` is
   framework-standard (`Color.lerp` per field, all 16 fields). The new
   float-space `Color.lerp` interpolates in exact float components —
   `lerp(black, white, 0.5)` stores `0.5`, which **quantizes to `#808080`**
   via `toARGB32()` (128/255 rounds up). Values like `surface #0A0A0A →
   white` at 0.5 are `0.5196` components (correct midpoint, NOT `#808080`).
   Documented in the tests so a future reader does not "fix" the lerp.
3. **Contrast re-verification (pure Dart):** all 16 doc ratios re-verified
   with `AppColors.contrastRatio` at **tolerance 0.02** (was 0.05) +
   the doc's two cross ratios (white-on-`glowPink` 3.50:1, white-on-
   `glowPinkDeep` 5.87:1). Hand-computed spot checks: pink L=0.24992 →
   5.998:1 ✓, cyan 13.652:1 ✓, gold 13.715:1 ✓, silver 11.542:1 ✓,
   bronze 6.678:1 ✓, violet 4.959:1 ✓.
4. **Tests** (`test/design_tokens/app_colors_test.dart`, +9): semantic alias
   mapping (roles → tokens, every alias ∈ `AppColors.all`), full-field lerp
   midpoint per channel, per-field copyWith completeness, `context.samayColors`
   resolution + fallback, tightened doc-ratio assertions.
5. **Docs:** this log + TODO.md workstream block.

## Decisions made and why

- **Task-prompt paraphrase vs the doc:** the mission brief listed "hairline
  #333333"; the doc §2.1 (THE CONTRACT) says `hairline #1A1A1A` /
  `border #333333`. Followed the doc — current code was already correct.
- **Semantic aliases are role names, not colors:** the doc has no
  status/success/error/danger hex table; the aliases encode its usage-column
  roles onto canonical tokens (§8.1 "extending the system" — no new color
  without a doc row). `success`→`discoCyan` is the one interpretation the
  doc leaves open (positive signal); flagged for U-30's finalization.
- **Aliases live on `AppColors`, NOT on `SamayThemeExtension`:** the
  extension stays the 16 canonical fields with complete copyWith/lerp;
  aliases are palette facts, not theme facts. `context.samayColors` resolves
  the canonical palette.
- **Lerp implementation unchanged:** `Color.lerp` per field is the
  framework-standard interpolation (`ThemeData.lerp` uses the same).
- **Doc-ratio tolerance tightened 0.05 → 0.02** — computed values sit
  within 0.005 of the doc's rounded numbers.

## MISTAKE

- **Test-writing error (fixed):** my first lerp test asserted every field's
  black→white midpoint equals `#808080`. Wrong for non-black start colors —
  `surface #0A0A0A → white` at 0.5 is `0.5196` components (correct
  midpoint). Lesson: the midpoint of *a palette field* is
  `(start + white)/2`, not `#808080`; only pure black→white quantizes to
  `#808080`.
