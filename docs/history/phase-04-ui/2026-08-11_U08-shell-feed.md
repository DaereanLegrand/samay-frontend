## Decisions made and why

- **Featured card keeps the §5.3 glowPink border (doc wins over the mission's
  "hairline cards"):** the design doc is the contract ("implementers may not
  silently deviate") and §5.3 explicitly reserves the glowPink 1px border for
  the featured feed card — the I-58 implementation already matched it. The
  mission's "hairline" is read as hairline-*thin* (1px, `Border.all` width 1)
  — the same geometry as the event cards' `hairline` borders. The badge
  becomes the glowPink `VBadge.accent` ('DESTACADO') so the pink signal is
  doubly carried (border + badge — §2.5 rule 5: color is never the only
  signal, the badge text carries it).
- **`VBadge` replaces the private `_Badge` on both card types:** §5.5
  variants are the canonical badge implementation (default = `border
  #333333` + white uppercase `labelSmall`; accent = border + same-color
  label, black fill). The custom `_Badge` duplicated the accent variant with
  inline styles — deleted as dead code. Side effect (intended, per §3.3):
  badge labels render uppercase ('DESTACADO', 'JUERGA', 'EVENTO DE GRUPO').
- **Two `VDiscoDivider` placements, not three:** header→content always
  (when events exist) + featured→list (when both exist). No divider above
  the empty state (a separator over "no events" would signal a missing
  section) and none when the feed is empty. Spacing: `xl` above/below the
  header divider, `screenHorizontal` padding everywhere.
- **Banner verification lives in `app_router_test` (not a new file):** the
  shell-banner interaction needs the full router harness (fake auth → shell
  redirect) + Supabase init, which that file already has; `_newContainer`
  gained an `extras` param so the connectivity stream override composes with
  the existing fakes. `app.dart` itself needed NO change — the `builder`
  placement above the Navigator already covers shell routes (the test pins it
  so a future move to a per-screen banner fails red).
- **Formatting: restored to HEAD + semantic edits only** (see MISTAKE) —
  the current SDK's tall-style formatter reflows the repo's older-style
  files wholesale; U-07's precedent ("pure churn is not a restyle") wins.
  Verified: `git diff -w` == `git diff` on all 6 touched files.

## MISTAKE

- **`dart format` tall-style churn (caught, reverted):** after GREEN I ran
  `dart format --set-exit-if-changed` on my 7 files — the current SDK
  reflowed pre-existing code wholesale (`listEvents([` arg-splits, indented
  `ProviderContainer(overrides: [...])` lists, etc.), inflating
  `test/router/app_router_test.dart` to a 529-line diff vs ~60 lines of real
  change. Same hazard U-07 documented. Fixed by rebuilding each file from
  `git show HEAD:<path>` + re-applying ONLY the semantic edits, then
  verifying `git diff -w` == `git diff` (zero whitespace-only lines). Never
  blanket-format repo files formatted by an older SDK style.
- **RED first run included a wrong-reason failure (self-caught):**
  `restyle_test.dart` initially missed the `Event` model import (the fake's
  `getEventByInviteToken` return type) — compile error, not a behavior
  failure. Fixed the harness before reading the RED results (a red test must
  be red because the behavior is missing, per DEVELOPMENT-WORKFLOW §1.3).
