## Deviations from the report (each justified)

1. **R3 l10n key count:** the report estimated "2 new l10n keys"; the screen needed **8** (`authBackToLogin` shared with R1 + `authForgotPasswordTitle/Heading/Hint/Send/SuccessTitle/SuccessBody/Snack`). A real screen has a title, heading, explainer, button, success title/body and snackbar — the estimate was low, not the scope.
2. **R3 "repoint the existing forgot-password assertion":** the report said `auth_interactions_test.dart` pins the inline-button behavior — it does **not** (verified by grep); the actual assertions live in `test/features/auth_screens_test.dart:105` and `integration_test/auth_flow_test.dart:46`, and both only assert the *label* ("Olvidé mi contraseña"), which still renders — no repoint needed. The behavior change is pinned by the new navigation test instead.
3. **R3 guard change:** the report's literal text only says "register the route + wire the button", but `AuthGuard` would redirect logged-out users away from `/forgot-password` (it is neither `welcome`/`login` nor under `authPrefix`). Added it to `isPublicRoute` — the minimal change that makes the route reachable (Juega has no guard to mirror; this is the Samay-shaped equivalent). Per the report's "route table +1" contract, authenticated users are NOT redirected (the pinned `_FakeAuthNotifier` table test renders the screen) — a deep link from a signed-in session is harmless.
4. **R2 counter at 0:** rendered literally per the spec ("when `_failedAttempts > 0`") — so "Te quedan 0 intentos" + the block message both show at the terminal state (Juega shows the same redundancy).
5. **`conventions_test.dart` (meta):** the I-69 route-gating audit fails on any undeclared route; `/forgot-password` added to `liveRoutes` (auth flow, no kill-switch — consistent with `login`/`verify`). Not in the report (it predates the route) but required for a green full suite.

## MISTAKE blocks

- **MISTAKE (RED-phase bug in my own test):** the first back-to-login test asserted the OTP screen was gone after `pump(300ms)` — the go_router exit transition wasn't finished, so the screen was still mounted. Fixed by `pumpAndSettle` (the OTP countdown timer is cancelled on dispose, so it settles cleanly). No production code involved.
- **MISTAKE (implementation bug caught by my own test):** the first forgot-password implementation validated the email shape but never rendered the error — the invalid-email test caught it (RED at GREEN time). Fixed by holding the validator message in `_emailError` state and passing it to `VInput.errorText` (`_emailError ?? auth.errorMessage` — validation first, auth error second).
