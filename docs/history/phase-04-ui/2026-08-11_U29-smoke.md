## 2. The smoke's two real bugs (found + fixed)

### BUG 1 — the OTP funnel flips to `RouteErrorScreen` on ANY auth emission (production bug)

**RED evidence:** the OTP stop failed: after entering a wrong code, the screen
vanished — `RouteErrorScreen` "Faltan los datos del registro" replaced it.
Probe prints in the route builders showed the exact mechanism:
`verify builder extra=VerifyExtra` (push) → auth emission → `extra=null`
(re-parse).

**Root cause (go_router 14.8.1 internals, traced through the SDK):** the app
wires `refreshListenable` to every auth-state emission
(`ref.listen(authStateProvider) → authRefresh.refresh()` — NAV-07). go_router
re-parses the engine route-information state on every refresh; pushed-page
extras are JSON-serialized into that state (`RouteMatchListCodec`); a non-JSON
extra (any typed `RouteExtra`) serializes as **null** with only a debug log
(`_RouteMatchListEncoder._toPrimitives`, `match.dart:890`). The re-parse then
rebuilds the pushed page with `state.extra == null` → `RouteErrorScreen`. The
REAL notifier emits `AsyncLoading` on every `verifyOtp` — so in production the
OTP screen would flip to the error screen on the first verification attempt
(the widget tests never caught it: `otp_ux_test` uses a minimal router without
the refresh wiring; no flow pushed `/auth/verify` through the real router with
an auth emission).

**Fix (TDD, RED → GREEN):**
- `lib/core/router/route_extras.dart` — NEW `RouteExtraCodec` (a go_router
  `extraCodec`): encodes the four typed extras (`VerifyExtra`, `AgeGateExtra`,
  `PrivacyTermsExtra`, `ProfileSetupExtra`) into JSON-able tagged maps and
  decodes them back through the existing `fromObject` factories; everything
  else (null, plain maps, the donate-shards group name String) passes through.
- Value equality (`==`/`hashCode`) on the four extras — the re-parsed config
  then compares EQUAL to the current one, so go_router's `setNewRoutePath`
  early-returns and the pushed screens keep their state (counter, consents,
  form) instead of remounting.
- `lib/core/router/app_router.dart` — `extraCodec: const RouteExtraCodec()` on
  the `GoRouter`.
- `test/router/route_extras_test.dart` — +8 tests (value equality ×5, codec
  round-trip ×2, passthrough ×1), RED-proven (compile-RED), 26/26 green.

### BUG 2 — U-18's NAV-08 tab pages dropped their name → telemetry silent on the shell

The telemetry shell flow (`screen_view` per tab) failed with `sink.events ==
[]`. Root cause: U-18's `_tabPage` builds `NoTransitionPage(key: state.pageKey,
child: child)` — a custom pageBuilder must set `RouteSettings.name` itself
(go_router's DEFAULT pages get `name: state.name ?? state.path`); the custom
page had `name: null` → the I-68 `RouterObserver` ignored every tab screen.
Regression introduced at U-18, never caught (the full integration suite was
not re-run after the U-series).

**Fix:** `_tabPage` now passes `name: state.name ?? state.path` — the default
naming restored. The telemetry flow's dedupe pin (one `screen_view` per tab)
went green again. Verified pre-existing: the flow fails identically with the
`extraCodec` wiring removed (isolation run).

## 8. Decisions made and why

- **The smoke is the runner's FIRST flow.** It is the definition of the core
  loop; a red smoke means the feature flows would fail anyway — fail fast.
- **Fixed BUG 1 with the codec + value equality, not by loosening the route
  builders.** Alternatives considered and rejected: (a) tolerating a null
  extra in the verify builder would silently break the funnel (no email to
  continue with); (b) pushing plain maps instead of typed extras would work
  but discards the NAV-04 typed-extra contract. The codec keeps the typed
  extras AND makes the refresh a no-op (the pushed screens keep their state —
  the attempts counter survives the emission, so the R2 budget can't be
  bypassed by a remount). This is the fix go_router's own warning suggests
  ("Consider provide a codec to GoRouter").
- **Fixed BUG 2 by restoring go_router's default page naming.** The telemetry
  contract (I-68) is `RouteSettings.name`; a custom pageBuilder that omits it
  silently unplugs the observer. `name: state.name ?? state.path` is exactly
  what the default MaterialPage/NoTransitionPage adapter sets
  (`builder.dart:376`).
- **U-05 drift fixed in the integration mirror** (not in the widget contract) —
  the uppercase badge is the pinned §3.3 contract; the mirror was stale.
- **Reduced-motion assertion is app-level, not widget-level:** toggling
  `accessibilityFeaturesTestValue` flips the flag for the WHOLE app (the
  MediaQuery inside MaterialApp reads the platform dispatcher), which is the
  honest §6.2/§7.5 behavior — and pumpAndSettle settles because everything is
  static. The ticker/resume edges stay the widget tests' territory (U-18's
  v_breathing_glow_test).
