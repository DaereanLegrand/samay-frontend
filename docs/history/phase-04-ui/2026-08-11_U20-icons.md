## What was built

### 1. The regenerable source icon — `tools/icon_gen.dart` (NEW)

A deterministic, dependency-free Dart generator for the launcher icon art:

```
dart run tools/icon_gen.dart
```

writes (byte-identical on every run — verified via `shasum` across re-runs):

| Asset | Size | Type | Role |
|---|---|---|---|
| `assets/icons/app_icon.png` | 1024×1024, RGB, **1.30 MB** | opaque | `image_path` (android legacy + iOS) |
| `assets/icons/app_icon_foreground.png` | 1024×1024, RGBA, 1.02 MB | transparent bg | `adaptive_icon_foreground` |

**Design (the disco identity per §1/§2/§5.6):** black `#000000` background
(P1) → soft pink glow halo (glowPink `#FF2E88`, α 0.5 core feathered to 0 —
the §4.3 glow-stack semantics, deterministic smoothstep falloff) → bold
white diamond outline (the VShardIcon shard, sharp 26px band, zero rounding
per §4.2) → solid glowPink inner shard. Rendered with exact point-in-polygon
half-plane distances + 2×2 supersampling (sharp edges, no blur), plus a
deterministic hash-based ±2/255 grain (splitmix32-style) that guarantees the
≥1 MB / non-uniform-pixels contracts and kills gradient banding; the grain
is invisible at any launcher size (averages out at ≤48 px). The whole
artwork (halo radius 420 < mask radius 337) sits inside the adaptive
foreground's 66 % safe circle, so no extra centering scale is needed.

**MISTAKE (dart:ui):** the brief suggested "a small Dart script under tools/
that uses dart:ui". Verified empirically that the standalone VM cannot load
`dart:ui` ("Dart library 'dart:ui' is not available on this platform" —
Flutter 3.44.1/Dart 3.12.1) — dart:ui is an engine library, unavailable to
`dart run`. Rather than routing the generator through the flutter tester
(which would make the committed tool unrunnable from the CLI), the script
renders procedurally (pure geometry) and encodes PNG by hand (IHDR/IDAT/IEND
+ CRC32, zlib level 9 via `dart:io`) — zero packages, runs anywhere,
fully regenerable. Decision: pure-Dart geometric renderer (the brief's
"or a simpler approach" clause).

## Decisions made and why

1. **Pure-Dart renderer over dart:ui** — dart:ui is unavailable to the
   standalone VM (verified); a pure-geometry + hand-rolled-PNG script keeps
   the committed tool runnable with a plain `dart run` (regenerable-icon
   contract). See the MISTAKE block.
2. **Grain (±2/255) shipped in the art** — guarantees the ≥1 MB source and
   the non-uniform-pixels test, prevents banding; invisible at launcher
   sizes. Deterministic hash noise (no RNG).
3. **Adaptive foreground as a separate transparent asset** + background
   declared as `#000000` color resource — matches Juega's proven pattern
   and the tool's requirements for `mipmap-anydpi-v26`; the black bg is a
   brand constant, not art.
4. **`android:label="Samay"`** — the M-29 issue #2 resolution per the repo
   naming convention (user-facing = Samay; internal pubspec/binary = samay).
5. **No `flutter: assets:` entry for the icons** — launcher icons are
   build-time resources consumed by the generator, not runtime bundle
   assets; declaring them would bloat the app bundle (fonts stay the only
   declared assets, per I-18's contract).
6. **No integration_test case** — launcher icons have no runtime surface;
   the asset/convention tests pin them on every `flutter test` run. The
   integration suite (I-01/U-29) covers runtime flows.
