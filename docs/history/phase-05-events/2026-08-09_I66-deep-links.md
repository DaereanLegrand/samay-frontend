## What was built

EINV deep-link foundation: `samay://event/{invite_token}` (MVP §6.3) parsing +
resolution + navigation, the invite-token route shadowing fix, and the app_links
platform wiring.

1. **`lib/core/deep_links/deep_link_handler.dart`** (new — I-66 owned):
   - `DeepLinkHandler` — two-layer parsing:
     - `parseDeepLink(String)` = **scheme gate**: `samay://` any shape, plus the
       https/http universal-link fallback restricted to event-shaped paths;
       null for non-Samay links (mailto, bare strings, non-event https paths).
     - `extractEventToken(Uri)` = **event-shape gate**: `event/<token>` path
       (trailing slashes tolerated), null otherwise. Future link types extend
       the scheme gate without touching `handleDeepLink` (S-12 audit input).
   - `handleDeepLink(String raw, {GoRouter router, resolveEventId, failureMessage})`
     — resolves token → eventId via an injectable callback, `router.go(RoutePaths.eventDetail(eventId))`,
     returns `bool`. Unknown token / non-Samay / resolver failure → `false` +
     localized snackbar (`routerInvalidInvite`) through
     `router.routerDelegate.navigatorKey` (go_router 14.x does not expose the
     key on the router itself). Resolver exceptions are swallowed (return false).
   - `deepLinkStreamProvider` — `Provider<Stream<String>?>` seam, **null default**
     (documented: null until the app_links wiring lands).
   - `DeepLinkListener` — app-root `ConsumerStatefulWidget`: subscribes to the
     seam stream and forwards each raw link to the handler; inert
     (`SizedBox.shrink`) when the provider is null. Mounted via
     `MaterialApp.router` `builder:` in `app.dart` (below `Localizations`, so
     the localized failure snackbar resolves).
2. **`lib/core/services/event_service.dart`** — `getEventByInviteToken(String)`
   → `Future<Event?>` (`events.invite_token` eq + `maybeSingle`; null when the
   token matches no event; typed `Event`). `invite_token` is UNIQUE + indexed
   (full_schema.sql §5), so the lookup is exact.
3. **`lib/features/events/events_providers.dart`** — `eventByInviteTokenProvider`
   (AsyncNotifierProvider.family, `Event?`).
4. **`lib/features/events/event_invite_route.dart`** (new) — `EventInviteRoute`:
   the token resolution widget — loading scaffold → detail (`EventDetailScreen(event.id)`)
   | not-found (`RouteErrorScreen` + `routerInvalidInvite`) | error (`ErrorView` +
   retry via provider invalidate).
5. **`lib/core/router/app_router.dart`** — the shadowing fix:
   - **Removed** the dead `/event/:inviteToken` route (it was SHADOWED by
     `/event/:eventId`, registered first — I-55's documented ordering issue;
     go_router matches by pattern so it was unreachable).
   - **ONE route** `/event/:eventId` now branches in `_eventDetailRoute`:
     UUID-parseable param (`Uuid.isValidUUID` with **`ValidationMode.nonStrict`** —
     format-only, see gotcha below) → `EventDetailScreen(eventId: param)` as
     today; non-UUID param → `EventInviteRoute(token: param)` (the invite-token
     deep-link path). I-03's hardened `RouteParams.fromState` access kept;
     empty/missing param → `RouteErrorScreen` (`routerEventNotFound`).
   - `RoutePaths.eventInviteToken` stays as the link/path builder (tests + the
     future EINV share screen use it).
6. **`lib/main.dart`** — app_links wiring: `ProviderContainer` with
   `deepLinkStreamProvider.overrideWithValue(AppLinks().uriLinkStream.map(...))`,
   `runApp(UncontrolledProviderScope(...))`. `AppLinks()` is touched **before
   runApp** so the cold-start link is captured (uriLinkStream delivers the
   initial link exactly once — Android native `initialLinkSent` guard — plus
   every later link; see research below).
7. **`lib/app.dart`** — `MaterialApp.router(builder: Stack([?child, DeepLinkListener()]))`.
8. **`pubspec.yaml`** — `app_links: ^7.0.0` (see decision below).
9. **Tests** (24 new) + 2 hermetic integration cases in `integration_test/events_flow_test.dart`.
10. **Docs** — this log + TODO.md workstream entry + PLAN.md EINV checklist lock.

## The app_links decision (research)

**DECISION: ADD the package.** `app_links ^7.0.0` resolves with ZERO friction:
it is already a **transitive dependency of `supabase_flutter` 2.12.4**
(`app_links: '>=6.2.0 <8.0.0'`) and is already a registered `native_build: true`
plugin on every platform (`ios/android/macos/windows/web` + `app_links_linux`) in
`.flutter-plugins-dependencies`. Declaring it directly pins the version without
adding a single new package (`pub get`: app_links stays 7.0.0, `dependency:
transitive → "direct main"`). Environment verified: Dart 3.12.1 ≥ ^3.12.0,
Flutter 3.44.1 ≥ 3.44.0. Sources: pub.dev/packages/app_links (7.2.1 current;
7.0.0 already resolved in the graph), `flutter pub deps` output.

API notes (7.x): the constructor takes **no parameters** — `onGenerateInitialDeepLink`
was removed in 7.0.0; the initial (cold-start) link is delivered through
`uriLinkStream` (Android: `AppLinksPlugin.java` `initialLinkSent` guard pushes
the launch intent through the event sink once on channel attach) and/or
`getInitialLink()`. **Stream-only wiring** in main() is therefore correct and
single-source: `uriLinkStream` covers the initial link + all subsequent links,
and subscribing early (before `runApp`) eliminates the cold-start race.

**Platform config (handoff → M-27/M-28):** the package compiles and registers
without it, but no link reaches the app until:
- **Android (M-27):** `<intent-filter>` with `android:scheme="samay"` + the
  App-Links intent filter for `https://app.samay.example.com/` (host placeholder
  per DEPLOYMENT-PLACEHOLDER.md R01) + the `assetlinks.json` file served at
  `https://app.samay.example.com/.well-known/assetlinks.json`.
- **iOS (M-28):** `CFBundleURLTypes` with `samay` URL scheme + Associated
  Domains `applinks:app.samay.example.com` (entitlements) + the
  `apple-app-site-association` file at the same placeholder host.
- S-12 (deep-link security audit) consumes `parseDeepLink`/`extractEventToken`
  + the handler as the parsing contract.

## Gotchas / decisions

- **MISTAKE (UUID validation mode):** `Uuid.isValidUUID` defaults to
  `ValidationMode.strictRFC9562`, which rejects the repo's all-1s test fixtures
  (`11111111-...` — non-RFC variant bits). If the default had been used, those
  params would take the TOKEN path and hit the network in router tests.
  **Fix:** `ValidationMode.nonStrict` (format-only: hex + dashes, accepts
  v1-v8 and the fixtures; verified against uuid 4.5.3).
- **Known limitation (documented):** `createEvent` currently generates the
  invite_token as a UUID v4 (`event_service.dart`), so a real UUID-shaped token
  link takes the "detail as today" branch and the detail provider's
  `getEvent` yields PGRST116 → the detail error view. This matches the mission's
  prescribed branch (UUID → detail as today) and the existing router tests.
  **EINV recommendation:** when the share screen lands, keep invite tokens
  non-UUID (e.g. short/random strings — the column is TEXT), or flip the
  `_eventDetailRoute` branch to id-fail → token-fallback in a follow-up.
- **go_router 14.x:** `navigatorKey` is a private constructor param; the public
  accessor is `router.routerDelegate.navigatorKey` (delegate.dart:192). The
  snackbar path is try/catch-guarded — mock routers in unit tests return null
  for the unstubbed delegate getter; the failure is still reported through
  `handleDeepLink`'s return value.
- **Stream subscription lifecycle:** `DeepLinkListener` subscribes in
  `initState` and cancels in `dispose` (unawaited — flutter_lints doesn't
  enable `unawaited_futures`); the broadcast controller from app_links closes
  itself when the last listener cancels (onCancel hook), so hot-restart leaks
  are avoided.
- **`comingSoonInvitation*` ARB keys** are now unused by app code (the dead
  `/event/:inviteToken` route was removed). Kept on purpose — the future EINV
  invite/share screens reuse "Invitación" copy; removing them would force
  gen-l10n churn on I-14/I-15's generated files.
- **Snackbar localization:** the handler falls back to
  `AppLocalizations.of(navigatorContext).routerInvalidInvite` when no
  `failureMessage` is passed (the widget tests assert the es copy).
- **Fake fallout:** adding `getEventByInviteToken` broke 3 `implements
  EventService` fakes (feed_test, photo_gallery_test, feed_flow_test) — added
  the throwing override + `Event` import to each (locks acquired).
