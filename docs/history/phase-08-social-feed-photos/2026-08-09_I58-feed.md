## Decisions

- **Providers are the single data seam** (I-11/I-50 direction): the screen
  watches `feedProvider`, never calls the service directly.
- **Radius filter defaults to anywhere while no location exists** — the
  mission's FOUNDATION instruction ("keep the filter UI functional with
  'anywhere' default"). `feedRadiusDefaultProvider` (config 50 km) is
  already plumbed for the future `LocationService` to consume.
- **Client-side public filter** — `EventService.listEvents(status:'upcoming')`
  is used unchanged (I-11's file is I-59's lock right now); group-scoped rows
  are dropped in the provider. A DB-level `group_id.is.null` filter can be
  added to the service when it's next touched.
- **No `geolocator` dependency added** — mission directive; the distance
  filter is explicitly future work (see Issues).
- **Reused I-55's `formatEventDateRange`** (exported from
  `lib/features/events/event_formatters.dart`) instead of inlining.
- **Covers are optional** in cards (`coverUrl != null`), mirroring
  event_detail_screen; avoids a hard dependency on cover uploads.
