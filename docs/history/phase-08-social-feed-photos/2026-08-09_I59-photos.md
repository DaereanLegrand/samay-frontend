## Decisions

1. **Bytes variant over file-path.** I-22's `ImageProcessor` yields bytes and
   image_picker's `XFile.readAsBytes()` gives them without a disk round-trip.
   `uploadEventPhotoBytes` is the primary seam (compress→PNG→insert);
   `uploadEventPhoto(filePath)` kept and delegates — no dead code, no callers
   broken, existing tests updated to the PNG contract (matches every other
   MediaService upload: "the stored object is always a PNG").
2. **Signed-URL strategy: TTL cache + refresh-on-demand, not 401-detection.**
   Signed URLs expire at a *known* time (1h), so the provider caches per
   photo and re-issues at `expiresAt − 5m` grace — the image layer never
   serves a URL that is about to die. A hard 401 (URL revoked early) is
   healed through `refreshSignedUrl(photoId)` (per-tile retry) and the cache
   never stores error responses. No Hive caching yet: the spec's "cache in
   Hive" step is deferred to I-67 (offline cache layer) — the in-memory cache
   already eliminates re-issuing per rebuild.
3. **Grid perf:** `GridView.builder` (lazy) — the H-27 guard remains green.
4. **Window rule:** open = `now ≤ ends_at + window_hours`; unknown event end
   is fail-closed (never advertise uploads for a broken row).

## Issues found (do not fix — report)

1. **Storage bucket `events` is created out-of-band.** No migration inserts
   `storage.buckets` rows anywhere in `supabase/migrations/` (verified by
   grep) — the `events`, `groups`, `avatars` buckets are provisioned manually
   (dashboard/`supabase storage` CLI) in this self-hosted setup. The
   `event_photos` INSERT (`eph_insert_own`) and `uploadBinary` will fail with
   404/PGRST until the bucket exists. **Recommendation:** add a guarded
   bucket-creation migration
   (`INSERT INTO storage.buckets (id, name, public) VALUES ('events',
   'events', false) ON CONFLICT (id) DO NOTHING;` + storage objects RLS
   policy `storage_objects_select_own`/`insert_own` mirroring the `avatars`
   convention) once the storage schema availability in this self-hosted stack
   is confirmed (S-09/M-track). Out of scope here — documented instead.
2. **Signed-URL 401 strategy** is expiry-based (see Decisions). A revoked-
   early URL needs the tile retry (`refreshSignedUrl`); there is no automatic
   on-error refetch inside `VNetworkImage` (it has no error callback). If the
   product wants silent auto-heal, extend `VNetworkImage` with an `onError`
   — follow-up, not PHUP-blocking.
3. **`event_photos` RLS lacks an upload-window check.** `eph_insert_own`
   (migration `20260809000002` §9) only checks `uploaded_by_user_id` +
   event access — the client enforces the 24h window, a malicious client can
   still INSERT after the window. S-03/S-09 candidate (server-side
   enforcement).
4. **I-61 in-flight breakage:** `lib/core/errors/app_error.dart` currently
   fails `dart analyze` (const constructor calling non-const super) — I-61's
   lock-held edit; all Flutter tests were un-runnable until it lands. Not
   mine to fix; re-verified after I-61 released.
