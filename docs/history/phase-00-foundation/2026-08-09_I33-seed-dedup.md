## Decisions made and why

- **Seed count 37 → 38 in Section 34 instead of keeping 37:** the mission mandates adding missing runtime keys; `app.search_debounce_ms` IS read by the app (`lib/features/friends/search_screen.dart:37`, `lib/features/groups/invite_screen.dart:48`) and was not seeded anywhere. Keeping the assertion at 37 would have made the post-reset test FAIL (a seeded key exists). Updating the expected value keeps the assertion valid; plan count untouched.
- **Added seed application to `migrate.sh`:** the script is documented (SELFHOSTING.md §3.1/§5) as the incremental path for existing DBs AND the only path for a fresh DB outside `reset.sh`. Since seed data no longer lives in the migration, migrate.sh must apply seed.sql to preserve prior behavior. Safe because every statement is `ON CONFLICT DO NOTHING`.
- **Runtime-key audit scope:** grepped `lib/` for every `app_config` consumer. Exactly 4 keys are read at runtime + 1 in a trigger: `economy.user_signup_shards` (config_service.dart:30, seeded ✓, fallback 256), `economy.group_shard_boost_days` (shards_service.dart:26, seeded ✓, fallback 14), `app.search_debounce_ms` (added; fallback 300 in lib), `chat.message_cap` (SQL trigger `enforce_message_cap`, seeded ✓, fallback 1000). All other seeded keys (`qr.*`, `events.*`, `groups.*`, `feed.*`, `minigame.*`, `ranks.*`, `subs.*`, `security.*`) are consumed server-side / by future Edge Functions — no lib/ readers, so no additions needed. No lib/ key lacks a documented fallback.
- **Kept the migration file intact** beyond §7 per mission (do NOT rewrite the 837-line file). Line count 837 → 792 (removed ~48 lines of seed inserts/comments, added ~8 comment lines).
