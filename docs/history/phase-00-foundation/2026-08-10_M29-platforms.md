## Decisions made and why

1. **macOS bundle name = `samay`, display name = `Samay`** — matches the
   repo-wide convention (pubspec `name: samay`, iOS CFBundleName `samay`,
   Android label `samay`, iOS CFBundleDisplayName `Samay`). `samay_app` was a
   pre-campaign rename artifact that no longer matches anything.
2. **MainMenu.xib "APP_NAME" left as-is** — stock Flutter template artifact
   (verified against the Flutter 3.44.1 template); macOS is not a product, and
   nib surgery buys nothing.
3. **Binary names (`samay_app` / `samay_app.exe` / `Makefile APP_NAME`) kept** —
   build-level identity; changing them churns the desktop build systems and the
   iOS install IPA path for zero user-visible gain. Documented + pinned in the
   gate.
4. **web theme/background `#000000`** — the app is dark-only (DISCO §1 P1);
   the template blue was pure scaffolding cruft.
5. **GeneratedPluginRegistrant.swift + Podfile.lock stay committed** —
   deterministic regenerable-state contract (same rationale as M-28's iOS
   Podfile.lock pinning); Pods/ + ephemeral/ stay gitignored (the template
   default). "flutter create .-style workflows" keep working: all four dirs
   remain intact scaffolds.
