## Findings

1. **Ciphertext-only-server is a chat-integration property, not yet live**
   end-to-end: `lib/features/chat` (I-56) + `chat_service` (I-38) encrypt
   before sending when the E2EE flag is on, and `messages.content` is the
   ciphertext field — but the client flow needs a full live-stack E2EE smoke
   (two real devices, X3DH handshake + ratchet exchange) before chat ships.
   Recommend a live `opt-009-e2ee-chat.sh` when the chat UI is reachable
   (Phase 07).
2. **Randomness:** key generation uses the `cryptography` package's secure
   RNG; no `Random()` key material found (grep-verified); test suite asserts
   non-determinism.
3. **No home-brewed crypto:** all constructions are standard library
   compositions; no hand-rolled primitives (grep-verified: no custom
   cipher/curve code).
