## 2. What migration 20260809000002 fixes (11 sections)

1. **G-03 users mass-assignment** — `REVOKE UPDATE (personal_shards, preshards, subscription_tier, subscription_expires_at, banned_at, ban_reason, date_of_birth) ON public.users FROM authenticated, anon` + `BEFORE INSERT OR UPDATE` trigger `assert_safe_user_update()` (SECURITY INVOKER, `SET search_path = ''`): INSERT normalizes protected columns (signup grant from app_config); UPDATE blocks changes unless the effective role has BYPASSRLS/superuser; `deleted_at` NULL→NOT NULL self soft-delete preserved (auth_service.softDeleteUser), clearing it (self-un-delete) blocked. Column REVOKE is the PostgREST-safe block (policies can't restrict columns); the trigger is defense-in-depth + the only way to express the one-way deleted_at rule.
2. **Admin RPC EXECUTE lockdown (CRITICAL)** — `grant_shards`, `grant_preshards`, `distribute_shards`, `recalculate_ranks`, `hard_delete_expired_users` were SECURITY DEFINER with default PUBLIC EXECUTE → any anon/authenticated caller could mint shards / drain pools via PostgREST. Now `REVOKE EXECUTE FROM PUBLIC` + `GRANT EXECUTE TO service_role` (pg_cron runs as postgres — unaffected; donate_shards_to_group/check_signup_email already hardened — untouched).
3. `user_cosmetics_update_own` — WITH CHECK added.
4. `friendships_update_own` — WITH CHECK added.
5. groups — `REVOKE INSERT (group_shards, size_tier, frozen_at)`, `REVOKE UPDATE (group_shards, size_tier, frozen_at, rank_bracket)` FROM authenticated, anon.
6. events — `REVOKE UPDATE (preshards_distributed, featured, featured_until)` FROM authenticated, anon.
7. messages — `messages_read_participant` aligned with `chats_read_participant` (group-member branch); `messages_insert_own` gains participation WITH CHECK.
8. `ep_insert_promotor` — event creator may insert self as first promotor (fixes createEvent chicken-and-egg).
9. event_photos — `eph_read_access` + `eph_insert_own` aligned with `events_read_access` (event_promotores branch) + insert access check.
10. `epl_insert_own` — photo-access WITH CHECK.
11. group_members — new SECURITY DEFINER STABLE helper `is_group_member(uuid)` (bypasses RLS → recursion-proof; `SET search_path = ''`); `group_members_read_same` restored (member lists); `group_members_insert_creator` → `group_members_insert_promotor` (creator self-insert + promotor invites, no empty-group heuristic); `group_members_update_own_status` (invitee self-accept, role pinned 'member'); `group_members_update_promotor` WITH CHECK.
12. `groups_delete_own` + `chats_delete_related` (creator-only; leaveGroup empty-group cleanup).
13. `REVOKE SELECT ON user_search_view FROM anon` (authenticated search only).
