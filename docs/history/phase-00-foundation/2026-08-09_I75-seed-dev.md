## Decisions made and why

- **Separate file, not default:** `seed.sql` stays the single source of truth
  for production seed (SUP-04/I-33). `seed-dev.sql` is demo-only and opt-in —
  matching the mission's "production seed stays clean" requirement.
- **Trigger interplay documented, not fought:** `assert_safe_user_update()`
  (20260809000002 §1.2) is SECURITY INVOKER, but the file is applied as
  `postgres` (superuser) → privileged branch → balances/tier values are
  preserved verbatim. `group_size_tier_trigger` recomputes size_tier on every
  member insert, so a 5-member group can never reach 'small' honestly —
  'After Club Lima' is force-set to 'small' by a final `UPDATE` (after all
  member inserts) so both tier UIs are exercisable; the header comment + log
  note that the next membership change recomputes it to 'micro' (correct
  trigger behavior). `group_shards_increment_trigger` inflates
  `groups.group_shards` from contributions — realistic, expected.
- **ON CONFLICT targets per real constraints:** friendships has NO unique
  pair constraint → `(id)`; group_members/chat_participants/event_promotores/
  event_invites/user_cosmetics use their real `UNIQUE` pairs; everything else
  `(id)`. Verified by the static gate.
- **Fake envelope honest-by-comment:** the `SME2.` message is marked as a
  demo placeholder; chat_service decrypt fails → 'Mensaje no descifrable'
  (the documented E2EE UX), which is what a dev needs to see.
- **tools/seed_dev_data.sh exists** because FILE-OWNERSHIP maps it to I-75;
  it is the same operation as the Makefile target, kept as the standalone
  entry point.

## MISTAKE / gotcha

- **MISTAKE (test parser, fixed):** first run of the static gate reported
  `users.interest_tags`/`discovery_opt_in` as missing — my `ALTER TABLE ADD
  COLUMN` grep was single-line but migration 0004 puts `ADD COLUMN` on the
  line AFTER `ALTER TABLE public.users`. Rewrote the check in awk (same-line
  AND next-line forms). Also caught `group_members.status` (20260512000011 is
  single-line `ALTER TABLE group_members ADD COLUMN IF NOT EXISTS status …`).
- **MISTAKE (test parser, fixed):** UUID "uniqueness" check counted FK
  references (same UUID repeated in many rows) as duplicates. Now only the
  row-id position (first `('uuid'` of each VALUES tuple) counts.
- **Gotcha:** `make -n` output includes the `cd supabase &&` prefix — the
  static check greps for `-p 54382` + `-f seed-dev.sql`, not a full command
  string.
- **Gotcha (documented limitation):** demo users have NO `auth.users` rows →
  they cannot log in. They ARE visible in feed/search (user_search_view)/
  party finder (discovery_view)/leaderboards/public events. To exercise
  member-scoped rows (groups, group chat) with your own account, add your
  `auth.uid()` to `group_members` + `chat_participants` — exact SQL snippet
  is in the seed-dev.sql header.
