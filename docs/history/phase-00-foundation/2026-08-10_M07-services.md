## 3. Decisions made and why

1. **Add edge-runtime + imgproxy; defer supavisor.** The mission bias held: both pinned images and
   env contracts are stable and parse cleanly (verified against the official compose + the images'
   sources); supavisor is an explicit repo convention ("pooler disabled — not needed for dev",
   AGENTS.md), `config.toml`/`pooler.exs`/`.env` all say disabled, and its official port mapping
   would collide with Samay's approved map — deferred with full evidence, documented in the delta
   table.
2. **The edge-runtime REQUIRES a `main` service entrypoint — the mission's ".gitkeep + README only"
   would crash-loop the container.** Verified in edge-runtime v1.74.0 source: the main worker
   resolves `index.{ts,tsx,js,mjs,jsx}` inside `--main-service`; when missing it falls back to the
   directory URL, which cannot be loaded as an ES module → `main worker boot error` → process exit →
   `restart: unless-stopped` loop → `docker compose up -d --wait` hangs. The 5-line
   `main/index.ts` boot placeholder (a `Deno.serve` health responder) is NOT EEDG function code —
   it is container infrastructure, exactly like a healthcheck. Documented in the file header, the
   README, and this log; EEDG replaces it.
3. **Mount `./functions` instead of the official `./volumes/functions`.** The mission mandates
   `supabase/functions/` (and it is the supabase-CLI convention — `supabase functions deploy`
   reads `functions/` from the stack root). Both stacks mount the same relative path, so parity
   holds. Deviation documented in the compose comment + SELFHOSTING §2.4.
4. **Functions route: cors only, no key-auth** (official pattern; VERIFY_JWT is the functions'
   own gate). Kept `read_timeout: 150000` for long-running functions.
5. **`${IMGPROXY_AUTO_WEBP:-true}` / `${FUNCTIONS_VERIFY_JWT:-false}` defaults** instead of bare
   `${VAR}` (official form) — Samay's standalone-clean parse contract (M-06 precedent); a future
   `.env` can override without editing compose (DKR-03).
6. **Container-name upstreams** (`samay-functions`, `samay-imgproxy`) — consistent with every other
   kong.yml/compose upstream in the repo (M-09 convention).

## MISTAKE / gotcha

- **MISTAKE (mine, fixed during the mission):** my compose edit inserted the `functions` service
  INSIDE `studio`'s `depends_on` block — the edit tool's substring match hit the 6-space
  `      meta:` line (studio's depends_on entry) instead of the 2-space `  meta:` service header,
  producing invalid YAML (`docker compose config` failed). Caught by the parse gate, repaired both
  stacks (studio depends_on restored + functions hoisted to top level), and re-verified all 9
  combos. Lesson: verify `docker compose config` immediately after each compose edit; don't batch
  service insertions after an ambiguous `  meta:` anchor.
- **Gotcha (research — edge-runtime env):** NONE of `SUPABASE_URL`/`SUPABASE_ANON_KEY`/
  `SUPABASE_SERVICE_ROLE_KEY`/`SUPABASE_DB_URL`/`SUPABASE_PUBLISHABLE_KEYS`/`SUPABASE_SECRET_KEYS`/
  `VERIFY_JWT` are read at boot by edge-runtime v1.74.0 — they are `std::env::vars()` pass-throughs
  to the Deno worker (verified: zero references in `crates/`/`cli/` Rust sources). The ONLY hard
  boot requirements are: an existing main-service entrypoint (gotcha above) and the TCP 9000
  listen. This is why the env can be set to the official values without risk.
- **Gotcha (research — imgproxy vs S3):** the official `docker-compose.s3.yml` does NOT configure
  imgproxy for S3 (`IMGPROXY_LOCAL_FILESYSTEM_ROOT: /` + the storage bind mount only serve the FILE
  backend). Samay's default stack runs the s3 override (M-06), so `/render/image/...` transformation
  of MinIO-stored objects would not resolve — the app currently uploads raw bytes (I-59) and never
  calls the render endpoint, so this is a documented limitation, not a regression. The s3.yml
  stays untouched (official parity); flagged for S-06/S-09.
- **Pre-existing (reported, NOT fixed — M-08's scope):** SELFHOSTING §2.1 target table still lists
  `analytics` as "not present" (Logflare optional, DKR-07) and the `supavisor` row still reads
  "missing (disabled)" — M-07 updated the §1.1 delta table + §6 row 21; the §2.1 port table's
  analytics row remains M-08's to flip when the logging override lands.
