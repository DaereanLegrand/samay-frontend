## Decisions made and why

- **Follow SELFHOSTING.md §2.1 exactly** as the target state (single source of truth):
  db 54382:5432, kong 54386:8000 + 54443:8443, studio 54381:3000, mailpit 54384:8025,
  auth/rest/realtime/storage/meta unpublished.
- **Remove (not remap) host publishing for auth/rest/realtime/storage/meta**: the approved
  map has no host port for them and `check_ports.sh` flags any host binding outside the
  approved values; the stack only exposes the 6 approved host ports. Container-internal
  ports (9999/3000/4000/5000/8080/5432) stay untouched — only the `ports:` blocks were
  dropped.
- **No secrets or image-tag changes**: M-01..M-05/M-09 own pinning, healthchecks, and key
  alignment. Diff kept minimal and parseable.
- **`.env` gitignored but still edited**: `check_ports.sh` scans them and they are part of
  the D-08 deviation rows; they are the documented source of env defaults.
- **Migration copy is byte-identical** (not adapted): the testing stack must mirror prod
  SQL exactly (only the pgTAP header note differs, D-04's file).

## MISTAKE / gotcha

- **MISTAKE (avoided by design):** removing `ports:` from a service block while leaving a
  trailing blank structure would be harmless, but removing the whole block cleanly is
  required so `check_ports.sh`'s `parse_compose` doesn't misattribute the next service's
  mapping. Verified parse after edits, not assumed.
- **Gotcha:** `reset.sh` previously ran `psql -h localhost` with no `-p` → host port 5432
  = **Juega's pooler**. `-p 54382` added to BOTH psql invocations (migrations + seed).
- **Gotcha:** `tools/agent_lock.sh acquire` blocks up to 1800s per file; the batch acquire
  timed out at 120s wall time on `test/router/app_router_test.dart` because
  I-03-router-hardening holds that lock — waited, then moved on (per AGENT-RULES §1).
- **Gotcha:** `docker compose config --quiet` in `supabase/` failed at baseline on the
  duplicate `deno-cache:` key *before* any port could be checked — fixed first.
