## Residual risks (report-only — S-03 follow-ups / product decisions)

1. **Table-level default grants (`arwdDxtm` to anon/authenticated) remain** on
   all tables from the image defaults. The G-03/39d column REVOKEs are
   defeated at the privilege layer (`has_column_privilege` resolves UPDATE via
   the table grant); enforcement today = RLS row scoping + the guard
   triggers. Clean fix: REVOKE table UPDATE/INSERT/DELETE from
   authenticated+anon and column-GRANT the app-writable columns per table
   (needs the full app write-surface enumeration — group_service,
   event_service, user_service, minigame, notifications, cosmetics — with
   live regression verification). **Recommend S-03 follow-up or dedicated
   hardening agent pre-Alpha.**
2. **pgTAP harness functions live in `public`** (~1000 helpers, incl. `plan`,
   `ok`) — anon-executable via PostgREST, inert test-only. Move to a private
   schema (or `DROP EXTENSION` after CI).
3. **is_group_member carries PUBLIC execute** (`=X`) — required by RLS policy
   evaluation; the grant is per-query scoped; acceptable.
4. **Anonymous `users` INSERT policy has no WITH CHECK restriction**
   (`users_insert_own` → `id = auth.uid()` is enforced — verified; the
   pg_policies `with_check` shows the check). All other INSERT policies
   verified own-row or role-gated (chats_insert_related, epl/eph/ep
   promotor-gated, messages sender-gated).
5. **event_qr_tokens** INSERT/UPDATE are server-only today; when QR Edge
   Functions land (QEDG), the tokens' rotation path must go through
   service_role only.
