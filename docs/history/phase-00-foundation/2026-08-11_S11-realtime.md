## Findings

1. **`DB_ENC_KEY=supabaserealtime` (dev default)** — the WAL encryption key;
   must be a real secret before any non-local deployment (same class as
   JWT_SECRET; add to the SECURITY.md runbook list).
2. **Subscription storms are unthrottled** (S-10 finding applies): a
   client can open many channels (per-event/status). When Kong rate limiting
   lands, add a per-consumer channel/subscription cap (or realtime's own
   connection limits — config `max_connections` if the version supports it).
3. `qr-token` channel payloads are QR tokens — verify the attendance RPC
   consumption model still enforces `max_failed_qr_validations` when EEDG
   lands (FLMT chain).
