### 4. E2EE backup-exclusion review (keychain + Hive) — documented, no code change

Per the I-37 key policy + E2EE-ARCHITECTURE.md §9.4 ("NO plaintext backups.
No cloud sync of key material"):

- **Keychain (flutter_secure_storage 9.2.4):** uses the app-default keychain
  access group — **no Keychain Sharing entitlement needed** (that is only for
  cross-app/extension sharing). Default accessibility in 9.2.4 is
  after-first-unlock; items restore with an ENCRYPTED device backup but are
  NOT synced to other devices via iCloud Keychain (no sync entitlement
  configured) → "no iCloud sync of key material" holds. **Documented, no
  change.** (Stricter no-backup would be `KeychainAccessibility.first_unlock_this_device`
  in `IOSOptions` — a storage-service change owned by I-26/S-18, left as
  handoff.)
- **Hive boxes (storage_service.dart, I-26):** `Hive.initFlutter()` →
  `getApplicationDocumentsDirectory()` → iOS **Documents/** (the mission note
  said "Application Support" — actual home is Documents), which IS included in
  device backups. The boxes are AES-256 encrypted with the 32-byte key in the
  keychain (never on disk beside the data — storage_service.dart:26-35).
  Restore consistency: encrypted backup restores BOTH boxes + keychain entry,
  or (keychain lost) `HiveService` re-creates the boxes empty — the documented
  I-26 key-loss degradation. Backing up the *ciphertext* is not "key material
  in backups" (§9.4 is about plaintext/key material). **Decision: document +
  do NOT exclude** — exclusion (`NSURLIsExcludedFromBackupKey` on the Hive
  dir) would break restore consistency for a disposable cache and needs a
  platform-channel or third-party plugin in the storage service (I-26's file).
  **Handoff S-18/M-32:** if strict no-backup of even ciphertext is required,
  set `NSURLIsExcludedFromBackupKey` on the Hive dir at `init()`.

## Decisions made and why

- **PHPhotoLibraryAddUsageDescription added now** (forward-compatible): the
  add-only key is required when the app saves to the gallery without reading
  it; the collage/cover-export is future work, but the key is zero-cost today
  and prevents an App-Store review rejection later. App Store "photos add"
  privacy label also needs it (S-14 scope, noted).
- **`pod update PurchasesHybridCommon` over deleting Podfile.lock:** narrower,
  and it is exactly what CocoaPods asked for; the regenerated lock is the
  single source of truth. Verified `pod install` (plain) now succeeds.
- **Hive boxes NOT excluded from backup:** disposable AES-256 caches; the key
  never leaves the keychain; the I-26 key-loss path already handles restore
  mismatches. Excluding would add a platform-channel dependency into the
  storage service for zero security gain (ciphertext-only backups).
- **Manual signing kept:** the fastlane/Match contract (M-17) is Manual-based;
  placeholder team is the fail-safe (a real team id would require a real
  Apple team); `--no-codesign` builds (CI) are style-agnostic.
- **`flutter build ios --no-codesign --debug` was safe to run:** the pod
  versions resolve from the local cache (no network beyond it), no signing
  involved (`--no-codesign`), Xcode 26.6 + Flutter 3.44.1 installed.

  Support" — it actually stores in **Documents** (`Hive.initFlutter()` →
  `getApplicationDocumentsDirectory()`). Documents and Application Support are
  both backed up by default, so the conclusion (boxes DO back up) is
  unchanged, but the location cited in this log is corrected.
- **Gotcha (I-71's original error was a red herring):** the message says "run
  `pod update PurchasesHybridCommon`" — I-71 diagnosed it as a
  purchases_flutter conflict needing an SDK change; it was purely a stale
  lockfile + stale CDN index. No podspec pin, no Podfile change, no version
  bump was needed. The opt-008 §7 lock-file assertions now prevent regression.
- **Gotcha (build output):** the Apple Silicon simulator warning
  ("GoogleMLKit … do not support arm64 … iOS 26+ simulators") is a
  pre-existing mobile_scanner limitation — device builds work (validated), the
  repo's hermetic integration harness runs on macOS. Reported, out of scope.
