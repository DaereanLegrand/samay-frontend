## Decisions made and why

- **Self-contained rows, not seed-dev:** like opt-001, each test creates its
  own users/groups/events/chats with fixed UUIDs via svc_* and tears them down.
  SEED_DEV=1 (I-75) is an OPTION documented in each header (demo UUIDs
  `10000000-…` could be reused), but the default path keeps tests independent
  of seed state and of each other (unique UUID ranges per file: 4444…/5555…/
  6666…/7777… — opt-001 owns 1111…/2222…/3333…, no cross-file collision since
  `run_all_backend.sh` runs them all against one DB).
- **Fixed UUIDs + cleanup trap:** each file deletes its own rows
  (FK-safe order: photos → events → groups → users rows → auth users) so
  re-runs are idempotent. NOTE: `groups.created_by_user_id` has no ON DELETE
  CASCADE → groups must be deleted before the users rows.
- **message_cap in pgTAP, not curl:** a trigger function (returns `trigger`)
  cannot be invoked via PostgREST RPC; the opt-test asserts the observable
  contract (below-cap retention) and delegates existence/cap assertions to
  `supabase/tests/schema_test.sql` (I-77 owns that file).
- **return=representation helper (`*_repr`):** opt-001's `auth_patch` uses
  `Prefer: return=minimal` which makes UPDATE success and RLS-filtered no-op
  indistinguishable (both empty). I-76 added `auth_patch_repr` so a promotor
  update returns the row and a non-promotor update returns `[]`.
- **`fetch_prekey_bundle` fetcher ≠ owner:** the realistic X3DH flow fetches a
  *peer's* bundle; the test therefore uses two distinct auth users.

## MISTAKE / gotcha

- **MISTAKE (avoided):** first draft of opt-002 used `auth_patch` (return=minimal)
  for the "non-promotor update blocked" assertion — an RLS-filtered UPDATE and a
  successful UPDATE both return empty with that Prefer header. Fixed by the
  `return=representation` helper (see Decisions).
- **Gotcha (schema):** `events_update_promotor` has USING only (no WITH CHECK);
  PostgREST applies the USING expression as WITH CHECK for UPDATEs — the
  promotor-update test still works, but future column rewrites on events need
  the same `*_repr`-style verification.
- **Gotcha (RLS-read assertions):** PostgREST returns `[]` (not 42501) when RLS
  filters all rows — the tests accept both `[]` and error patterns, per
  test/README.md's interpretation table.
- **Gotcha (cleanup ordering):** `events` rows reference `groups(group_id)` and
  `event_photos`/`event_photo_likes` cascade from `events`; deleting events
  first avoids orphan check failures; `groups.created_by_user_id` (no cascade)
  forces group-before-users ordering (see Decisions).

  user's bundle. This is by design for X3DH (initiators must read the
  responder's public prekeys), but the mission brief described the function as
  "requiring auth.uid()" — the auth requirement is the EXECUTE grant, not a

  consumption rate limit is already a documented S-10 handoff in 0003).
