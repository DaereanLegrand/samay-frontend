# 2026-08-11 — S-04: PostgREST / SQL-injection audit (report)

**Agent:** S-04 (Phase 4.5 — Security) · **Mode:** report-only
**Scope:** every query-construction path in the Flutter app (`lib/`) and the
Go CLI/API (`internal/db`, `internal/ops`), plus the PostgREST-facing surface.

## Findings

### Dart (app)

| Path | Verdict | Evidence |
|---|---|---|
| `.or()` string interpolation | ✅ CLEAN | 0 hits repo-wide (SEC-02/C-04 held since 2026-07-24) |
| Filter operators | ✅ SAFE | All 16 filter sites use the typed builder API (`eq/neq/gt/gte/lt/lte/like/ilike/in` — `rest_client.dart` `RestFilter` switch); values are **URL/query-parameterized by PostgREST**, never interpolated into SQL |
| `searchUsers` `.ilike('username', '$query%')` | ✅ SAFE (residual) | Filter value only (parameterized); caller-side `InputSanitizer` (I-27) applies before the service; view is the 3-column `user_search_view` security barrier; `limit(20)` |
| Column names | ✅ SAFE | All `from('table')`/column literals are code constants (115 sites audited), no reflection from user input |

### Go (CLI + API server)

| Path | Verdict | Evidence |
|---|---|---|
| `QueryBuilder` filters | ✅ SAFE | `Eq/Neq/Gt/...` build `col=op.<url-escaped-value>` via `escapeValue` (`url.QueryEscape` + `*`/`+` handling, `query_builder.go:113-118`); column names are ops-code constants |
| PostgREST client | ✅ SAFE | `internal/db/client.go` — requests carry typed filters; no raw SQL strings |
| Server-side SQL | ✅ SAFE | No raw SQL in Go; all writes go through PostgREST/RLS |

### PostgREST surface (SQL-side)

- The only SQL executed with client influence is PostgREST's own parameterized
  filters + the SECURITY DEFINER RPCs — all 17 now search_path-hardened and
  role-gated (S-03 verified), incl. the NULL-safe `donate_shards_to_group`
  guard (20260811000001).

## Residuals

1. **Prefix-search enumeration** (ilike `%` prefix, authenticated-only):
   inherent to the feature; mitigate with rate limiting (S-10) and keep the
   `limit(20)`.
2. **Filter op allowlist** is enforced in `RestFilter` (unknown op →
   ArgumentError) — keep it that way when new repos land (refactorability
   doctrine: new features must not add raw `.or()` strings).
