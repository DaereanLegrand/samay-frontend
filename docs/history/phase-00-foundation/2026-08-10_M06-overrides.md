## Decisions made and why

- **MinIO images pinned to `minio/minio`/`minio/mc` (Docker Hub) instead of
  the official `cgr.dev/chainguard` tags.** The pin policy (§2.2) forbids
  floating tags; chainguard's are floating. Docker Hub tags are exact
  immutable RELEASE stamps; existence verified via the registry API
  (server `RELEASE.2025-09-07T16-13-09Z`, client `RELEASE.2025-08-13T08-35-41Z`
  — the newest available on both Docker Hub and quay.io).
- **`mc ready local` healthcheck kept** (official pattern): verified the
  `minio/minio` image ships `mc` (`Dockerfile.release`) and mc seeds the
  `local` alias → `http://localhost:9000` by default (`cmd/config-v10.go`
  `loadDefaults`), so the healthcheck works out of the box.
- **s3 stays in the default `COMPOSE_FILE`** (both `.env` files untouched —
  not in the lock list; M-01 verified + M-10 documented the layering). The
  default stack now runs MinIO; the file backend returns by dropping the
  override from `COMPOSE_FILE` or using base-only `-f` flags. Documented in
  §2.6 + §5. Checkpoint note: first `up` after this change pulls two new
  images and storage waits on bucket creation (healthy-before-start chain).
- **Creds via `${VAR:-default}` interpolation** (not bare `${VAR}` like the
  official file): keeps `docker compose config` warning-free/standalone-clean
  (no `.env` dependency) while allowing future `.env` override (M-13/S-08).
- **storage-api env mapping documented in the override header** so future
  readers never resurrect the dead `AWS_ENDPOINT`/`AWS_DEFAULT_REGION` names.

## MISTAKE / gotcha

- **MISTAKE (test bug, fixed before shipping):** `merged_has` passed the
  `--` separator to `docker compose` → compose v5 ends option parsing at
  `--`, so `config` became a docker-level command → "unknown docker command".
  RED-proven (2 failures) → fixed by splitting flags/patterns in the helper.
- **Gotcha (research):** storage-api v1.60.4 does NOT read
  `AWS_ENDPOINT`/`AWS_DEFAULT_REGION` (the pre-M-06 stub's vars) nor
  `GLOBAL_S3_PROTOCOL` (inert, kept for official parity) — the readable set
  is `STORAGE_S3_*`/`GLOBAL_S3_*` + `REGION` + AWS SDK default chain.
- **Gotcha (research):** `mc ready local` only works because mc's default
  config seeds the `local` alias (anonymous, localhost:9000) — NOT because
  any alias file is baked in the image.
- **Gotcha:** the official s3.yml uses bare `${MINIO_ROOT_USER}` interpolation
  (breaks standalone parse without `.env`); the `:-default` form was required
  for Samay's parse-clean contract.
- **Pre-existing (reported, NOT fixed):** `supabase/run.sh` still echoes a
  Mailpit endpoint for the prod stack that has no mailpit service (M-10 issue
  #1 — aligning it would break M-10's script parity gate; minefield for
  M-07/M-08 when mailpit formally lands or is dropped).

## Issues found / handoffs (reported, NOT fixed)

1. **Checkpoint stack-start note (behavioral change):** the default
   `COMPOSE_FILE` (unchanged) now layers a FUNCTIONAL s3 override → the next
   `docker compose up -d --wait` pulls `minio/minio` + `minio/mc` (2 new
   images) and storage only becomes healthy after minio is healthy AND
   minio-createbucket completes. The chain is designed to be self-healing
   (idempotent bucket create), but the first start is slower and needs the
   registry reachable. If the checkpoint prefers the file backend, start with
   `docker compose -f docker-compose.yml up -d --wait` or drop the s3 entry
   from `.env` `COMPOSE_FILE`.
2. **`minio-data` named volume survives `reset.sh`** (only
   `volumes/db/data` + `volumes/storage` are removed) — documented in
   §5 troubleshooting; a full teardown should
   `docker volume rm samay_minio-data` / `samay-testing_minio-data`.
3. **S3-protocol/presigned URL auth** (S-09/S-06, re-documented): the
   `storage-v1` Kong route's key-auth would 401 S3-protocol presigned
   requests (no `apikey`); the app's upload path sends `apikey`, so the
   override is safe for the app today.
4. **`supabase/run.sh` prints a Mailpit endpoint for the prod stack** with no
   mailpit service (M-10 issue #1, still open — see Decisions).
5. **Categories file status flips:** `docs/to-fix/categories/13-DOCKER-INFRASTRUCTURE.md`
   (DKR-02/DKR-08 rows) is D-03-owned — evidence in TODO.md + SELFHOSTING.md
   for D-03's re-verification (M-01/M-09/M-10 precedent).
6. **`imgproxy`/`functions`/`supavisor`** still absent (SELFHOSTING row 21) —
   M-07..M-08.
7. **storage-api `GLOBAL_S3_PROTOCOL` is inert** in v1.60.4 (kept for official
   parity) — future version bumps should re-verify before relying on it.
