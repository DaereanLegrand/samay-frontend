## Decisions made and why

- **Keep the `Samay Testing` prose identity in the testing scripts.** The
  mission requires scripts to differ ONLY by container-name prefixes; since the
  scripts contain no container names, the strict reading would make them
  byte-identical. But the reset warning ("destroy all data in the **Samay
  Testing** Supabase database") is an operator-safety string and the stack
  name is the same identity class as the container prefixes. Decision: keep
  the identity tokens, document them, and make the gate normalize them —
  behavior is byte-for-byte identical, and §9.4 fails on anything beyond
  identity. (Recorded here + SELFHOSTING §3.5 so V-04/D-03 can audit.)
- **Fix direction: `supabase/` is canonical** (per mission) — the testing
  script aligned to it, never the reverse.
- **`.env` files left untouched.** The mission excludes `.env*` from the
  strict diff ("read the keys to judge"). Judgment: every key/value delta is
  testing-vs-prod semantics (mailpit SMTP, domains, testing-only keys) with
  ZERO runtime consumers — the compose files hardcode the effective values
  identically in both stacks. Aligning them would either break testing email
  capture (mailpit) or inject fake prod creds. Documented, not changed.
- **Row 8 resolved as "target already met":** the target's own parenthetical
  says "site_url stays app origin" — `http://127.0.0.1:3000` IS the app origin
  (Flutter dev server); 3000 is not a mapped/Juega host binding and
  `check_ports.sh` classifies it INFO. I-02's original keep-as-is decision
  stands; the row text was ambiguous, now clarified with the flip.
- **Row 13 credited to I-47**: the `54321` test-harness reference was swept
  by I-47's port hygiene (H-18 evidence); M-10 re-verified line 280 = 54386.
- **config.toml byte-identity checked before the sed-normalized diff:** the
  current contract (approved ports + `project_id = "samay"` in both) admits
  zero differences; byte-identity is the strongest gate. The normalized-diff
  fallback exists for a future legitimate `project_id` divergence.

## MISTAKE / gotcha

- **MISTAKE (test bug, fixed before shipping):** §9.6's first version diffed
  absolute paths (`diff -rq "$REPO/supabase" …`), so the allowlist
  `grep -vxFf` matched nothing and the gate flagged all 11 intentional lines
  as "UNDOCUMENTED parity gaps". Fixed by running `(cd "$REPO" && diff -rq
  supabase supabase-testing)` — relative paths match the allowlist exactly.
- **Gotcha (history):** the `Mailpit UI:` drift predates the orchestration —
  it shipped in the `Vive→Samay` rename commit `ce904e9` and survived I-02's
  port remap because I-02 only touched the port numbers in the echo lines.
- **Gotcha (bash 3.2, macOS):** §9 uses only POSIX-`grep`/`sed -E`/`cmp`/
  `diff` + process substitution (`<( )` — supported by bash 3.2's `diff`
  invocation here); no associative arrays (M-01's lesson).
