## What was built

### 1. `internal/db/query_builder.go` (new)
Chainable `QueryBuilder` with `Select(columns...)`, `Eq/Neq/Gt/Gte/Lt/Lte`, `Like/ILike`,
`In(col, values...)`, `NotIsNull(col)`, `Order(col, asc)`, `Limit(n)`, `Offset(n)`.
`Build() (selectParams, filterQuery)` ready for `client.Select/Update/Delete`.

**Escaping (`escapeValue`):** `url.QueryEscape(v)` then:
- `%2A` → `*` restored — PostgREST documents `*` as the unescaped wildcard alias for
  `like`/`ilike` (docs.postgrest.org v12: "to avoid URL encoding you can use * as an alias of
  the percent sign %"). Existing test `TestListUsers_WithSearch` asserts raw `*alice*`.
- `+` → `%20` — space must not become `+` (ambiguous form-encoding decode across servers).

Result: `&`→`%26`, `=`→`%3D`, `,`→`%2C`, `(`/`)`→`%28`/`%29` (all from QueryEscape),
spaces→`%20`. **Dots are left unescaped deliberately:** PostgREST matches operators as known
prefixes (`eq.`/`ilike.`/…), so `key=eq.test.key` is unambiguous, and the mission's own escape
test list ( `&`, `=`, spaces, commas) omits dots. Escaping dots would break
`TestGetConfig_UsesKeyFilter` (asserts `key=eq.test.key`) for zero security gain in plain
filters. If `.or()`/`and()` building is ever added, dots must be re-escaped there (S-04 note).

### 2. `internal/db/crud.go` (new)
Generics on top of the client's *current public API*:
- `List[T](ctx, client, table, qb) ([]T, error)`
- `GetByID[T](ctx, client, table, id, qb) (*T, error)` — applies `Eq("id", id)` when `id != ""`
  (limit 1); when `id == ""` the qb must carry the identity filter (used by config `key` lookups).
- `Insert[T](ctx, client, table, row, qb) (*T, error)` — POST via `client.request` with
  `?select=` from qb (default `*`).
- `Update(ctx, client, table, qb, patch) error` — **refuses empty filters** (blocks accidental
  full-table PATCH).
- `Delete(ctx, client, table, qb) error` — **refuses empty filters** (blocks full-table DELETE).

All client calls go through 4 one-line seam functions (`selectRows/insertRow/updateRows/deleteRows`)
so I-39's ctx landing touches crud.go exactly where the seams are.

## Behavior fixes discovered along the way (GO-12 evidence)

1. **`users list --search` was broken**: old code emitted `username.ilike.*alice*` (dot between
   column and operator — invalid PostgREST). QueryBuilder emits `username=ilike.*alice*`.
   Updated `internal/ops/users_test.go` `TestListUsers_WithSearch` (one assertion; I-42-owned file,
   change locked + documented).
2. **`GetShardLedger` sent a duplicate `limit`**: filter string contained `&limit=10` AND
   `client.Select` appended `limit=<n>` — duplicate query params, ambiguous server behavior.
   I-39 independently removed the bogus `&limit=10`; QueryBuilder emits a single `limit`.
3. **Spaces in search/filter values crashed the CLI**: raw space in URL → `url.Parse` error.
   Now escaped (`%20`).
