## What was built

1. **`lib/core/logging/app_logger.dart`** (new) — `AppLogger` singleton, 5 levels (`debug/info/warn/error/emergency`):
   - Entries formatted `[Samay][LEVEL] <ISO-8601 UTC> message` + stack on its own line.
   - `debug`/`info` compiled out in release via `kReleaseMode` (LOG-02 fix d).
   - Synchronous append to `samay.log` in the app documents dir (`path_provider` → `getApplicationDocumentsDirectory()`); `debugPrint` kept **only** as fallback sink when file I/O fails (LOG-02 fix: "Keep `debugPrint` only as a fallback sink").
   - `knownBenignError(Object)` classifier (LOG-04): `Cancelled` → info, `Bad state: Future already completed` → info, `MissingPluginException` → warn; returns `null` for real errors. Extensible `_benignRules` pattern list.
   - Crash marker API (LOG-03): `markCrash()` writes `.samay_crash_marker` (timestamp+message+stack); `recoverCrashMarker()` appends it to persistent `samay_crash.log` and clears the marker; `readCrashMarker()`/`clearCrashMarker()` for roundtrip/testing.
   - **Testability:** `AppLogger(storageDir: Directory)` constructor override — tests inject a temp dir, never call `path_provider`.
   - **Extensibility (I-70):** small public surface (`log`/`debug`/`info`/`warn`/`error`/`emergency`/`knownBenignError`/crash-marker methods) so Sentry can be wrapped around it later.
2. **`lib/main.dart`** (rewired):
   - `FlutterError.onError` + `PlatformDispatcher.instance.onError` now log through `AppLogger`, classify via `knownBenignError()` (old `_explainError` logic moved into the logger), `markCrash()` on real errors (`unawaited`), keep `FlutterError.presentError(details)` / `return true`.
   - Startup: `AppLogger.instance.init()` then `recoverCrashMarker()` — appends pending marker to `samay_crash.log`, clears it, logs a warn. Recovery UI documented as future work (TODO comment).
3. **`debugPrint` sweep** — all 6 remaining call sites replaced with `AppLogger` calls (2 in `main.dart` were rewritten in step 2):

## Decisions made and why

- **Synchronous writes** (vs Juega's async 200-entry/2s-flush queue): mission explicitly allows sync; after kReleaseMode gating only warn/error/emergency reach the file in production, so volume is low. Buffered async writer is a later optimization (documented in LOG-02 residual).
- **`markCrash` does NOT itself append to `samay_crash.log`** — the append happens in `recoverCrashMarker()` at next launch (matches LOG-03 spec exactly and avoids double-logging).
- **`knownBenignError` returns `LogLevel?`** rather than bool, so downgrade and logging are one decision; `MissingPluginException` → `warn` (not fully dropped) since in production it can indicate a real plugin issue, and it's the test-harness noise case from the mission.
- **`instance` is a mutable static** (`static AppLogger instance = AppLogger()`) so tests can substitute an instance with a temp dir; I-70 can later swap in a Sentry-backed subclass.
- **path_provider added** (mission-sanctioned). Checked pubspec.lock resolved `path_provider 2.1.6`.
