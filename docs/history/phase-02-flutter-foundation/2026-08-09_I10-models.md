## Research (sources at bottom)

- **freezed 3.2.5** (latest stable, 2026-02) pins `analyzer >=9 <11`; **build_runner 2.16.0**
  (2026-08) pins `analyzer >=13.3 <15` → **the stable freezed line CANNOT co-exist with
  current build_runner**. Only **freezed 4.0.0-dev.3** (2026-06-13) supports analyzer 13.
  The 4.0.0-dev line is the analyzer-13 port (breaking change: no `final` in constructor
  params — irrelevant for `@freezed` factory syntax; `when`/`map` removed — replaced by
  Dart 3 sealed-class pattern matching, which is the modern best practice anyway).
- **Flutter 3.44.1 pins `meta` to exactly 1.18.0** (sdk-version-pinning) → build_runner
  **2.15.2+** requires meta ^1.18.3 → incompatible. Resolved at **build_runner 2.15.1**
  (analyzer >=8 <14) + **analyzer 13.0.0** (meta ^1.18.0) + freezed 4.0.0-dev.3.
- **`purchases_flutter` <9.0.0-beta.3 pins `freezed_annotation ^2.0.1`** → forced bump
  `^8.4.1 → ^10.8.0` (10.x dropped the freezed_annotation dep entirely; RevenueCat API is
  stable across majors; package is not yet imported anywhere in `lib/` — verified by rg).
- **Dart 3 sealed-class unions with freezed**: use `sealed class X with _$X` and built-in
  `switch` pattern matching; `when`/`map` are legacy (freezed README). Not needed yet — the
  7 models are single-constructor data classes; unions land with state models (SM-06, I-12).
- **build_runner 2.15.1 removed `--delete-conflicting-outputs`** ("These options have been
  removed and were ignored") — plain `dart run build_runner build` is enough.

## Decisions

1. **Toolchain:** `freezed_annotation ^3.1.0` + `json_annotation ^4.12.0` (deps);
   `build_runner ^2.15.1` + `freezed ^4.0.0-dev.3` + `json_serializable ^6.14.1` (dev deps).
   Resolved: analyzer 13.0.0 / meta 1.18.0 / build 4.0.7 / source_gen 4.2.4 / dart_style 3.1.9.
2. **Generated files are COMMITTED** (team convention per TOOL-01; Juega does the same —
   39+ generated files committed). No `.gitignore` changes.
3. **JSON keys = DB column names** via `@JsonSerializable(fieldRename: FieldRename.snake)`
   on the factory constructor (freezed forwards it to the generated class) — matches
   `supabase/migrations/20260510000001_full_schema.sql` and current service select columns.
4. **Stringly-typed enum-like fields** (`type`, `status`, `role`, `sizeTier`, `rankBracket`,
   `subscriptionTier`) — NOT Dart enums yet. Rationale: DB enums grow (unknown future values
   would crash `fromJson`); app today consumes them as strings everywhere; swapping to a
   `@JsonValue` enum later is a one-line change per field. Refactorability-first.
5. **`GroupMember.username`** is a *getter* over the real `users` embed
   (`@JsonKey(name: 'users') Map<String, dynamic>? users`): PostgREST returns
   `users: {username: ...}` (nested), not a flat key — see screens reading
   `m['users']?['username']` (group_detail_screen.dart:221). First attempt (custom
   `@JsonKey(fromJson: _usernameFromJson)` with a private static converter) broke codegen
   (see MISTAKE).
6. **Defaults** via `@Default(...)` (freezed auto-adds `@JsonKey(defaultValue:)`):
   personalShards/preshards/groupShards/preshardsPool = 0; subscriptionTier = 'free';
   role = 'member'; status = 'active'; read = false.
7. **`analysis_options.yaml`** (M-26-owned, one-line coordination change): added the
   standard freezed setup `analyzer.errors.invalid_annotation_target: ignore` — documented
   in the freezed README Install section, required because `@JsonSerializable` sits on a
   factory constructor in freezed source. Without it, 7 warnings pollute `dart analyze`
   (checkpoint gate). Flagged for M-26 to own going forward.
8. **Scope discipline:** no app-wide migration to models (I-11/I-44/I-51 consume them
   incrementally); no changes to category docs (D-03 owns them); only `docs/to-fix/TODO.md`
   status flips: **M-01 → ✅** (ARC-02), **H-12 → 🔄** (SM-05 — models exist, app-wide
   migration pending).

## MISTAKE / gotcha (self)

- **Custom `@JsonKey(fromJson:)` converters with private statics break freezed codegen.**
  freezed copies the annotation into the generated `_GroupMember` const constructor /
  getters where a bare `_usernameFromJson` reference is out of scope → "Undefined name" /
  "Not a constant expression" compile errors; the `.g.dart` silently ignored the converter
  and emitted a plain cast (`json['users'] as String?` — wrong shape). Fix: model the real
  payload (`Map<String, dynamic>? users` embed) + convenience getter.
- **freezed 3.2.5 (stable) + build_runner 2.16.0 (latest) are mutually exclusive** (analyzer
  9-10 vs 13.3+). Do not re-introduce `freezed: ^3.2.5` after a future analyzer bump.
- **`--delete-conflicting-outputs` no longer exists** in build_runner 2.15.1 (ignored
  warning) — harmless but don't rely on it.
- **`date_of_birth` is a `date` column** — `DateTime.parse('1998-06-15')` works, but
  `toJson` emits the full ISO string (`1998-06-15T00:00:00.000`), not `'1998-06-15'`.
  Test must assert `startsWith('1998-06-15')`, not equality.
