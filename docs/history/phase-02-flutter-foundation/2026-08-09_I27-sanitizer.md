## What was built

- **`lib/core/utils/input_sanitizer.dart`** — shared `InputSanitizer`:
  - `sanitize(input, {maxLength, normalizeNfkc = false})` — NFKC (opt-in) → strip Unicode `\p{Cc}\p{Cf}` (control + format incl. zero-width/bidi overrides) → trim → grapheme-cluster length cap.
  - `sanitizeOptional(input, {maxLength})` → `null` when empty (group description shape).
  - `sanitizeUsername(input)` — preserves case; NFKC always ON (identifier); strips whitespace + `@`; cap 20.
  - `sanitizeAmount(input)` — ASCII digits only, cap 9 digits (int-safe).
  - Field cap constants: username 20 · bio 160 · group name 50 · group description 250 · message 500 · search query 50 · amount 9.
- **Applied at write boundaries** (behavior identical for valid input — idempotent by design):
  - Username: `profile_setup_screen.dart` `_save()` + `auth_service.createUserProfile` (defense in depth at screen AND service).
  - Bio: `edit_profile_screen.dart` `_save()` (was `.trim()` only).
  - Group name/desc: `create_group_screen.dart` `_create()` + `group_service.createGroup` (desc → `sanitizeOptional`).
  - Search queries: `invite_screen.dart` + `search_screen.dart` (sanitize inside the debounced handler, before the provider query key).
  - Donate amount: `donate_shards_screen.dart` (digits-only before `int.tryParse`).
  - Message content: `chat_service.sendMessage` (future E2EE seam; sanitize now, encrypted payload inserted by I-38 will be base64url — control-char stripping stays valid).
- **Dependencies added:** `characters ^1.4.0` (grapheme-aware capping — already transitive via Flutter, now direct) and `unorm_dart ^0.3.2` (NFKC). `pubspec.lock` regenerated via `flutter pub get`.

## Decisions

1. **NFKC via `unorm_dart`** — Dart core has **no built-in Unicode normalization** (no `String.normalize()`). Research (pub.dev): `unorm_dart` (Dart port of walling/unorm, **Unicode 17.0 tables**, verified publisher, MIT, 202k downloads, CI badge) is the only solid maintained NFKC package. Juega's reference `InputSanitizer` uses the same package (`/Users/daerean/Codes/apps/Juega/lib/shared/utils/input_sanitizer.dart:1`). NFC-via-`characters` is NOT possible — `characters` only iterates grapheme clusters, it does not normalize.
2. **NFKC default OFF for free text** (bio/group desc/messages) — NFKC visibly rewrites user-typed characters (full-width → ASCII, ligatures split); for identifiers (username) it is always ON so canonically-equivalent/compatibility-lookalike inputs cannot register distinct accounts (SEC-06 homoglyph goal).
3. **Juega's cap uses `substring` (UTF-16)** — splits surrogate pairs. Ours caps by grapheme cluster (`characters.take`), verified by the emoji test. Improvement over the Juega reference.
4. **Juega keeps `\t\n\r`**; we strip **all** of `\p{Cc}` per the SEC-06 fix sketch — includes `\t\n\r`. Trade-off: multi-line free text loses line breaks. MVP fields are single-line (`VInput` default); chat send is a future seam — if chat becomes multi-line, add a `preserveNewlines` option (documented, not gold-plated).
5. **Client-side caps only** — DB has no length CHECK constraints (schema `20260510000001_full_schema.sql` has none). Server-side caps tracked in SECURITY.md §2.6 note (I-31/DB work). Screens should pair with `TextField.maxLength` for UX — noted in the class doc, not wired (screen restyle is U-05+).
