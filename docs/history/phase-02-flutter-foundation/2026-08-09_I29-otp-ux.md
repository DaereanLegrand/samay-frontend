## What was built

1. **OTP resend countdown** (`otp_verification_screen.dart`)
   - After the initial OTP send, the screen shows `Reenviar código (60s)` counting down
     (60 → 0) via a `Timer.periodic(1s)` started in `initState` and cancelled in `dispose`
     (dispose-safe; no `setState` after unmount — the timer is dead before the state is).
   - The resend button is disabled while the countdown runs; at 0 it flips to the enabled
     `Reenviar código` label.
   - Tap → `authStateProvider.notifier.sendOtp(email)` (the existing send flow) →
     countdown restarts, failed-attempt counter resets, code field clears.
   - Cooldown value: `OtpVerificationScreen.resendCooldownSeconds = 60`, constants
     `maxFailedAttempts = 5`, `otpCodeLength = 6` live on the widget (typed, single source).
     `SamayDurations` was NOT used — it is the *animation* token set (150-500ms); a 60s
     cooldown is not an animation duration (documented in the code comment).
2. **Wrong-attempt guard (client-side cap)**
   - `_verify()` detects failure via `authStateProvider.hasError` after `verifyOtp` (the
     notifier maps every failure to `AsyncError`).
   - On failure: counter++, code field cleared, `AppLogger.instance.warn(...)` logs the
     attempt (`N/5` + email). At 5 consecutive failures the screen enters a **blocked
     state**: inline blocking message (`authOtpTooManyAttempts`), verify button disabled,
     auto-submit disabled. Only a resend (new code) unblocks — it resets the counter.
   - The block is per-code and per-screen-session (consecutive failures); a new code resets
     the streak.
3. **Auto-submit on 6 digits (AUTH spec gap)**
   - `TextField.onChanged` → when the field reaches 6 digits (and not blocked, not already
     verifying) `_verify()` fires automatically; the manual `Verificar` button is kept.
4. **Signup screen hardening** (`signup_contact_screen.dart`)
   - Double-tap guard: `VButton(loading: auth.isLoading)` already gates during `sendOtp`
     (the notifier sets `AsyncLoading`), but the pre-check (`checkEmail`) phase runs with
     no loading state — added a local `_submitting` flag covering the whole `_signup()`
     body, gated the button with `loading: auth.isLoading || _submitting`.
   - Rate-limit errors: verified `showAppError(context, e, blocking: true)` already maps
     `RateLimitError` (error_mapper `over_email_send_rate_limit` / `over_request_rate_limit`)
     to the friendly `errorsRateLimit` message ("Demasiadas solicitudes. Espera un
     momento."). Added an `AppLogger` warn on the `RateLimitError` branch for observability.
5. **ARB keys** (es + en, with metadata; parity guaranteed by `test/l10n/l10n_test.dart`):
   `authResendCode`, `authResendCodeIn({seconds})`, `authOtpTooManyAttempts`.

## Tests (RED → GREEN)

`test/features/auth/otp_ux_test.dart` (new) — 6 widget tests using a
`_RecordingAuthNotifier extends AuthNotifier` (records `verifyOtp`/`sendOtp` calls,
configurable failure) injected via `authStateProvider.overrideWith`:

- countdown ticks 60 → 59 → 0 and disables resend until elapsed (`tester.pump` durations);
  at 0 the button enables and tapping it records `sendOtp` and restarts the countdown.
- auto-submit fires on the 6th digit (records `verifyOtp('123456')`); manual `Verificar`
  still works (2nd call).
- 5 consecutive failures → blocked state (blocking message visible, verify button disabled,
  further input does NOT auto-submit); resend clears the block and resets the counter
  (6th failure after resend is just failure 1 — no block).
- success keeps navigating to the age-gate route.

Note: countdown/auto-submit are timer-driven UX — widget tests with `tester.pump` are the
right layer; a hermetic integration-test addition was skipped deliberately (real-time
integration runs cannot fast-forward a 60s timer; `auth_flow_test.dart` keeps covering the
auth navigation surface). `auth_screens_test.dart` needed no harness change (its OTP test
uses `pumpAndSettle`, which now simply pumps through the 60s of fake time — still green).

## MISTAKE blocks

- **MISTAKE (test harness, timer discipline):** `pumpAndSettle` after pumping the OTP screen
  would keep advancing fake time until the 60s countdown expires (each tick schedules a
  frame) — fine, but slow and easy to misread. Countdown tests use explicit
  `tester.pump(Duration(...))`; every test ends with the timer expired or the tree unmounted
  (`pumpWidget(SizedBox())`) to avoid "periodic Timer still pending" failures.
- **MISTAKE (attempted):** using `SamayDurations.standard` for the cooldown — wrong token
  class (animations only). Resolved: dedicated widget constant `resendCooldownSeconds`.
- **MISTAKE (design iteration):** first draft cleared the code field on *any* non-error
  early return (unauthenticated success); that would have wiped input on the
  "already-registered" path. Final: field clears only on failure/blocked/resend.
