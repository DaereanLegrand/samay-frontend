# I-65 — Theme-mode persistence (UI-05 / L-16) (2026-08-09)

**Agent:** I-65-theme-persistence | **Phase:** 02-flutter-foundation | **Status:** DONE

## What was built

Findings **UI-05 / L-16** ("Only dark mode — no light theme, no theme
persistence, no system-preference detection") — closed. The dark-only state is
**intentional** (DISCO-DESIGN-SYSTEM §1 P1 "black always"), so the deliverable
is the persistence + the 'system' seam, not a light theme:

1. **`lib/core/providers/theme_provider.dart`** (new, I-65-owned):
   - `hiveServiceProvider` — the injectable seam over the encrypted Hive
     `config_cache` (I-26). Production: `HiveService()` (init'd in `main()`
     by I-26, `lib/main.dart:55`). Tests: override with an in-memory fake.
   - `themeModeProvider` = `AsyncNotifierProvider<ThemeModeNotifier,
     ThemeMode>` (H-08 convention: no legacy `StateNotifierProvider`).
   - `ThemeModeNotifier.build()` loads the persisted mode at startup from the
     config cache under `theme.mode` (`'dark'` default | `'system'`);
     unknown/absent values and any cache read failure (incl. uninitialized
     Hive → `HiveError: Box not found…`) degrade to `ThemeMode.dark` with an
     `AppLogger.warn` — a preference never blocks boot (I-26 key-loss
     degradation is treated as a cache miss).
   - `setThemeMode(ThemeMode)` — optimistic state update + `cacheConfig`
     persist under `theme.mode`; persistence failures are logged, never
     surfaced.

2. **`lib/app.dart`** — `SamayApp` (ConsumerWidget) now watches
   `themeModeProvider` and wires `MaterialApp.router(theme: SamayTheme.dark,
   darkTheme: SamayTheme.dark, themeMode: <persisted>)`. `'system'` resolves
   to the disco dark theme on most devices (both slots are the same theme) —
   the *seam* is the refactorability deliverable; no visual change.

3. **`lib/features/profile/settings_screen.dart`** — new `_ThemeSection`
   (reusable const sub-widget, PERF-08 pattern): 'Tema' label + full-width
   `SegmentedButton<ThemeMode>` with Oscuro (default) / Sistema segments,
   persisted through the provider. Inserted after the Notificaciones row.
   The `themePersistence` feature flag (I-49) is left dark/untouched — the
   toggle ships ungated per the mission (the toggle IS the deliverable); the
   flag remains available as a kill-switch/remote-config knob.

4. **l10n** — 3 new ARB keys es/en (`settingsTheme` Tema/Theme,
   `settingsThemeDark` Oscuro/Dark, `settingsThemeSystem` Sistema/System);
   `flutter gen-l10n` once (getters `settingsTheme*` in `AppLocalizations`).

## Decisions made and why

- **AsyncNotifier over StateNotifier** — H-08/STAT convention (I-09 migrated
  the codebase off `StateNotifierProvider`); the `AsyncValue` also gives a
  natural `AsyncLoading` first frame, handled at both call sites with
  `valueOrNull ?? ThemeMode.dark`.
- **Hive config cache over SecureStorage/SharedPreferences** — the encrypted
  `config_cache` box (SEC-10/I-26) already exists and is init'd in `main()`
  before first reads; `cacheConfig`/`getCachedConfig` (putAll — preserves
  other keys) are the exact API needed. Theme preference is non-sensitive but
  the encrypted box costs nothing and centralizes local persistence (I-71
  will use the same seam for app_config).
- **`'theme.mode'` cache key, values `'dark'`/`'system'`** — mirrors the
  provider's `ThemeMode.name` values so no mapping table is needed; a future
  light theme adds a `'light'` arm in `_modeFor` only.
- **Optimistic state + logged persistence failures** — a settings toggle must
  never show an error for a cache write failure; dark default is the brand,
  and a lost write just means next boot returns to the previous choice.
- **SegmentedButton over Switch** — the mode is a 2-value choice with a
  future third option ('light'); SegmentedButton expresses the seam and is
  testable via its `selected` set. Labels only (no icons) — minimal disco
  style + no Ahem-font overflow risk.
- **Toggle ungated by `themePersistence` flag** — the flag (I-49) stays
  `false` as a kill-switch knob; the mission delivers the visible toggle.
  Flag default tests in `test/core/feature_flags_test.dart` untouched.
- **No real-Hive integration test** — same precedent as I-26: the hermetic
  suite cannot exercise Keychain/platform channels; the flow covers the
  provider seam through a fake HiveService, widget tests cover the real
  `HiveService().getCachedConfig()` fallback path (uninitialized Hive).
