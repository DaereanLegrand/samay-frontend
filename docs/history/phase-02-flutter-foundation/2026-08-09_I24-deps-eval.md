## 1. Resolution evidence (exact, reproducible)

Scratch attempt (`pubspec.yaml` only, lockfile regenerated, no commit):

```yaml
  flutter_riverpod: ^3.4.2   # + riverpod: ^3.4.2, go_router: ^17.3.0
```

`flutter pub get` → **version solving failed**. Root cause chain, verbatim from the solver:

1. `riverpod >=3.0.0-dev.12 depends on test ^1.0.0` — riverpod 3.x ships its new testing
   utilities (`ProviderContainer.test()`, `WidgetTester.container`) **in the package itself**
   and declares `test` as a **runtime** dependency (verified against pub.dev API:
   `riverpod 3.4.2 deps: {..., 'test': '^1.0.0', ...}`).
2. `test` 1.16.6+ requires `yaml ^2.0.0` — **conflicts with our pinned `yaml: ^3.1.3`**
   (dev_dependency, used by `test/pubspec_test.dart`).
3. `test` (all versions compatible with flutter_test) requires `analyzer >=8.0.0 <13.0.0` —
   **conflicts with our pinned `freezed: ^4.0.0-dev.3`** (needs `analyzer ^13.0.0`; it is the
   newest freezed on pub — `no versions of freezed match >4.0.0-dev.3 <5.0.0`).
4. Secondary wrinkle (blocks even a freezed/yaml downgrade alone): recent `test` versions need
   `test_api 0.7.13` / `matcher <0.12.19`, while this Flutter SDK's `flutter_test` pins
   `test_api 0.7.11` + `matcher 0.12.19` — the compatible `test` window is narrow.

pub's own suggestion: `flutter pub add dev:freezed:^3.2.6-dev.1` — i.e. **the upgrade cannot
happen without downgrading/regenerating another agent's pinned deps** (freezed is I-10's
models/generation stack; yaml is used by I-48's `pubspec_test.dart`).

**SDK note:** Flutter 3.44.1 bundles Dart 3.12.1, so `riverpod 3.4.2`'s `sdk: ^3.12.0` is
satisfiable; the `test` dependency conflict is the sole resolver blocker.

**go_router alone resolves:** with riverpod 2.6.1 held, `go_router: ^17.3.0` → **17.4.0**
resolves and `dart analyze` shows **zero new issues** (0 errors attributable to the change;
the 61 errors currently visible in the working tree are pre-existing I-27 in-progress files,
present with the original lockfile too).

## 2. Research — API diff tables (for the eventual migration)

### 2.1 Riverpod 2.6.1 → 3.x (upstream: riverpod.dev/docs/whats_new, flutter_riverpod CHANGELOG 3.0.0)

| API (2.x) | 3.x | Impact on Samay |
|---|---|---|
| `AsyncValue.valueOrNull` | **renamed to `.value`** (`valueOrNull` removed; old `.value` semantics gone) | ~30 call sites across `auth_provider.dart`, all feature providers' consumers, screens, tests |
| `AsyncNotifier.state.copyWithPrevious(const AsyncLoading())` | `copyWithPrevious` now `@internal`; new pattern `state = const AsyncLoading()` (loading no longer carries previous value; use `when(skipLoadingOnReload:)` for that) | 5 sites in `AuthNotifier` (`signIn`/`sendOtp`/`verifyOtp`/`signUp`/`createProfile`) |
| Provider failure handling | **automatic retry ON by default** (exponential backoff 200ms→6.4s, **retries forever**); `provider.future` skips intermediate error states while retrying; reading a failed provider rethrows wrapped `ProviderException` | TEST LANDMINE: every test asserting `AsyncError` from a throwing `build()` (profile/friends/groups screen tests, `profile_providers_test`) would hang or need `retry: (c, e) => null` on every `ProviderContainer`/`ProviderScope` |
| `FamilyNotifier`/variants | fused into `Notifier` (arg via constructor) | only affects sync notifiers — we use `AsyncNotifier`/`FamilyAsyncNotifier` (families remain `AsyncNotifierProvider.family`) |
| `AsyncValue.value` during error | returns `null` (was: threw / odd) | safe after the `valueOrNull→value` rename |
| `AsyncValue.when(...)` | unchanged shape | no migration needed |
| `ref.listen` / `ref.listenManual` | still exist (`listenManual` kept, `weak:` flags added) | `edit_profile_screen.dart:28`, `app_router.dart:54` unchanged |
| `updateShouldNotify` | all providers now compare with `==` | `AuthState`/`FriendRequestsData` don't override `==` → effectively identical semantics |
| Notifier lifecycle | Notifiers/Refs unusable after dispose; recreated on rebuild | `_FakeAuthNotifier` pin pattern in `app_router_test.dart` still valid (state setter override + `build()`); verify on migration |
| `StateProvider`/`StateNotifierProvider`/`ChangeNotifierProvider` | moved to `package:*_riverpod/legacy.dart` | zero usage in Samay (H-08 already migrated to `AsyncNotifier`) |
| `ProviderContainer.test()` / `overrideWithBuild` / `tester.container()` | new | optional adoptions, not required |

**Riverpod migration touch-list** (when gate re-opens): `lib/core/providers/auth_provider.dart`
(rename + loading pattern), `lib/features/{friends,groups,profile}/*providers.dart` (rename),
`lib/core/providers/{config_provider,user_provider}.dart` (rename if touched), every screen
that reads `.valueOrNull` (login, otp, signup, profile_setup, profile, invite, search,
settings, delete_account, friends_list, requests, my_groups, group_detail, leaderboard,
edit_profile), `lib/core/router/app_router.dart` + `auth_guard.dart` (valueOrNull), and the
test files: `test/providers/*`, `test/router/*`, `test/features/*`, `integration_test/support/*`
(+ add `retry: (count, error) => null` to every test container).

### 2.2 go_router 14.8.1 → 17.x (upstream: pub.dev/packages/go_router/changelog)

| Version | Breaking change | Impact on Samay (non-typed routes) |
|---|---|---|
| 15.0.0 | URLs **case-sensitive** by default (`caseSensitive` param) | none — all `RoutePaths` lowercase; `authPrefix` `startsWith` guards unaffected |
| 16.0.0 | major bump for `GoRouteData` (typed routes) breaking changes | none — Samay does **not** use `GoRouteData`/`TypedGoRoute` (mission: do NOT adopt typed routes now; keep `RoutePaths` + `RouteExtras`, both version-agnostic) |
| 17.0.0 | `ShellRoute` navigation changes notify GoRouter observers by default (+ `notifyRootObserver` opt-out) | behavior addition; `MainShell`/`routerProvider` unaffected |
| 17.3.0 | min Flutter 3.38 / Dart 3.10 | satisfied (Flutter 3.44.1 / Dart 3.12.1) |

**Unchanged through 17.x:** `redirect: FutureOr<String?> Function(BuildContext, GoRouterState)`,
`ShellRoute.builder (context, state, child)`, `errorBuilder`, `refreshListenable`,
`GoRouterState.matchedLocation/pathParameters/extra`, `context.push/go/pop`.
⇒ **go_router 14.8.1 → 17.4.0 is a zero-code-change upgrade for Samay** (verified: resolves
+ `dart analyze` 0 new issues). It is held back only by the paired riverpod gate.

## 3. Migration plan (for re-execution when the gate re-opens)

### 3.1 Unblocking conditions (any of)
- **A.** Flutter SDK bumps so the bundled `flutter_test` accepts a `test` version compatible
  with `freezed 4.x`/`analyzer 13.x` (or riverpod drops the `test` runtime dep), **or**
- **B.** Coordinated dep change approved by orchestrator: downgrade `freezed` to `3.2.6-dev.1`
  (regenerate all 8 `.freezed.dart` via `build_runner` — I-10 coordination) **and** `yaml` to
  `^2.2.1` (verify `loadYaml` API in `test/pubspec_test.dart`), **or**
- **C.** Split the upgrade: ship **go_router 17.4.0 alone first** (zero code change, resolves
  now), then riverpod 3.x separately once A/B lands.

### 3.2 Step order (riverpod 3.x, ~90 min)
1. Lock `pubspec.yaml`, run `flutter pub get` (resolution green required, else abort).
2. **Mechanical rename** `valueOrNull` → `value` across `lib/` (grep `\.valueOrNull`).
3. `AuthNotifier`: replace 5× `state.copyWithPrevious(const AsyncLoading())` →
   `state = const AsyncLoading()`; audit `refresh()`/loading UX (loading no longer keeps
   previous data — consider `AsyncValue.when(skipLoadingOnReload: false)` where the old
   "keep previous" UX is wanted).
4. **Disable auto-retry in tests**: add `retry: (retryCount, error) => null` to every
   `ProviderContainer(`/`ProviderScope(` in `test/` + `integration_test/support/`
   (`test/providers/*`, `test/features/*`, `test/router/app_router_test.dart`, `auth_screens_test`,
   `integration_test/support/test_app.dart`). Decide app-side `ProviderScope(retry: ...)` policy
   in `main.dart` (default retry is a feature for prod).
5. Run `dart analyze` (expect 0 errors) → `flutter test` full suite; gate: **≥ 500 pass,
   only 12 structure_test failures**.
6. Update `AGENTS.md` canonical provider patterns (DEP-13 fix text) + docs.

### 3.3 Risks
- **Auto-retry semantics** are the #1 regression source (hangs in error-state tests, changed
  `.future` behavior, `ProviderException` wrapping on `ref.read`). Must land with step 4.
- `FamilyAsyncNotifier` family-fusion edge cases must be re-verified against the actual 3.x
  source (changelog wording differs from generated-code reality) **before** the code rename.
- Loading UX regression from dropping `copyWithPrevious` (button spinners already keyed on
  `auth.isLoading` — verify `login_screen`/`signup_contact` still show spinners).
- Other agents' in-flight pubspec edits (I-27 sanitizer currently holds `pubspec.yaml`/`pubspec.lock`
  locks) — coordinate lock ownership.
