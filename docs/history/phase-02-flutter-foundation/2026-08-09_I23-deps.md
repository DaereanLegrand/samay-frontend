## MISTAKE / gotcha

- **Concurrent `flutter pub add` (I-24, lockless) collided with my `pub get` window.** Mid-session
  I observed `pubspec.yaml` briefly containing `go_router: ^17.3.0` (I-24's in-progress
  riverpod/go_router upgrade) and a `flutter pub get` failure (`samay depends on both yaml
  ^3.1.3 and freezed ^4.0.0-dev.3`). The bump was made WITHOUT holding the pubspec.yaml lock
  (I held it) — a semaphore violation by tool bypass (`flutter pub add` doesn't go through
  `agent_lock.sh`). It reverted itself when the resolution failed. Verify with `git diff` /
  re-read before assuming your own edit state. Lesson for the orchestrator: agents running
  `flutter pub add` must acquire the pubspec.yaml lock first (or use the `run` one-shot form).
- **Do not chain lock acquires in one command** (I-18's MISTAKE echoed): a held lock makes a
  chained `acquire` wait up to the timeout and blows the 120s tool window. Acquire one per call.
- **Re-verify pubspec.yaml before/after every `flutter pub get`** when concurrent agents are
  active — transient foreign edits (even reverted ones) make reads lie.
