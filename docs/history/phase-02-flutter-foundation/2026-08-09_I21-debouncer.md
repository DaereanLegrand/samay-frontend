## 1. What was built

### `lib/core/utils/debouncer.dart` (new)
`Debouncer` class — the shared search-field debounce (finding PERF-05/L-24,
mirrors Juega's utility per `10-PERFORMANCE.md`):

- `Debouncer([Duration delay = 300ms])` — injectable delay for tests; `delay`
  is a mutable field so screens re-tune it from remote config without
  recreating the instance.
- `void run(VoidCallback action)` — cancels the pending timer and schedules
  `action` once after `delay` of quiet; every call replaces the previous
  pending action (N keystrokes ⇒ 1 execution).
- `void cancel()` — cancels the pending timer (idempotent); screens call it
  from `dispose`, making the debouncer dispose-safe (no timer can fire after
  the widget is gone).
- `void flush()` — runs the pending action immediately if one is scheduled and
  cancels the timer (no-op when idle); `bool isPending` exposes the state.

### `lib/features/groups/invite_screen.dart`

## 2. Decisions & rationale

1. **`Debouncer` in `lib/core/utils/`** — matches the repo's utility home
   (`async_ops.dart`, `retry.dart` convention) and FILE-OWNERSHIP (I-21 owns
   `lib/core/utils/debouncer.dart` + `invite_screen.dart`; search_screen is
   ⚙️-mine per mission).
2. **Mutable `delay` instead of per-`run` delay param** — screens read
   `app.search_debounce_ms` per keystroke today (search_screen legacy
   behavior). Making `delay` a field keeps that behavior byte-identical while
   keeping the `run(action)` signature clean and the utility testable
   (injectable delay).
3. **`testWidgets` + `tester.pump` instead of `fake_async`** — `fake_async`
   is only a transitive dep; importing it would trip
   `depend_on_referenced_packages` (analyzer warning). The widget-test fake
   clock drives `Timer` deterministically with zero pubspec changes.
4. **No new provider query on intermediate keystrokes** — debouncing the
   `_query` state update means the family `searchResultsProvider(arg)` is never
   instantiated for intermediate strings (this is the actual Supabase-query
   saving PERF-05 asked for).
5. **`if (mounted)` guard inside the debounced callback** — defense-in-depth;
   `dispose` already cancels the timer, so the guard is unreachable in
   practice but makes the debouncer explicitly dispose-safe.
