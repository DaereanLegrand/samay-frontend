### 1. `lib/core/services/telemetry_service.dart` (new — FILE-OWNERSHIP I-68 ✅)

The PostHog seam, mirroring the RevenueCat seam pattern (I-61 `RevenueCatService`/`RevenueCatDriver`):

- `posthogApiKey` / `posthogHost` — `const String.fromEnvironment('POSTHOG_API_KEY'/'POSTHOG_HOST', defaultValue: '')` build-time defines (I-34 dart-define convention). Placeholders only; real values are deploy-time (DEPLOYMENT-PLACEHOLDER.md R19).
- `TelemetrySink` — abstract delivery endpoint (`track`/`identify`/`reset`). The future posthog_flutter wiring implements it; tests inject a recording fake; stub mode never touches it. I-70 (Sentry around AppLogger) can mirror this same shape.
- `TelemetryService` — `isEnabled` is **true only when `POSTHOG_API_KEY` is non-empty** (per the mission seam spec; `POSTHOG_HOST` is carried for the future SDK init but does not gate). Stub mode: `track` logs the event name via `AppLogger.info` (compiled out in release — LOG-02 gating) and `identify`/`reset` are silent no-ops. Enabled mode: every `track` runs `sanitizeProperties` BEFORE the payload leaves the process; `identify(null|'')` is a no-op; enabled-without-sink degrades to the stub log (SDK wiring pending).
- `sanitizeProperties(Map<String, dynamic>)` — **pure, unit-tested** PII guard (SECURITY.md §2.8 contract):
  - keys whose lowercase form contains any of `email|password|token|phone` → value replaced with `'[redacted]'` (key kept so the analytics schema stays stable; substring match catches `user_email`, `access_token`, `phone_number`…);
  - string values > 500 chars → truncated to 500 + `…` (exactly 500 is untouched);
  - non-strings and everything else pass through unchanged (no recursion — telemetry properties are flat by design).
- `telemetryServiceProvider` — defined in this file (keeps I-11's `service_providers.dart` untouched, I-67 precedent).

### 2. `lib/core/telemetry/route_observer.dart` (new)

`RouterObserver extends NavigatorObserver` — reports `screen_view` with `{'screen': route.settings.name}` (go_router sets each page's name to the matched path, parameters filled, e.g. `/event/11111111-…`).

- Reports only when a **new** route becomes visible: `didPush` + `didReplace`. `didPop`/`didRemove` are ignored (the popped route was tracked when pushed; pops would double-count back-navigation).
- Ignores routes without a name (the shell page's root push carries no name — see the go_router investigation below).
- **Consecutive-same-screen dedupe**: go_router `go()` to the same location fires `didReplace` with the same name → not re-reported. A re-visit after a different screen IS reported.

## go_router observer investigation (why the shell needed a second observer)

go_router 14.8.1 source (`~/.pub-cache/.../go_router-14.8.1/lib/src/builder.dart`, `route.dart`):

1. `GoRouter(observers:)` → `GoRouterDelegate` → the ROOT `Router`/Navigator only.
2. The root shell page is pushed with `name: state.name ?? state.path` where the **ShellRouteMatch's state has both null** → the root observer sees `didPush(name: null)`, which the observer correctly ignores. Verified by a scratch test (deleted after use).
3. `ShellRoute` builds its own `_CustomNavigator` for the tab pages, and it receives `ShellRoute.observers` — NOT the GoRouter ones (route.dart `ShellRoute.buildWidget` → `_buildNavigatorForCurrentRoute(observers, …)` with the shell's own `observers` field). Without a shell-level observer, tab switches fire no events at all.
4. A single `NavigatorObserver` instance cannot attach to two navigators at once (framework assertion `observer.navigator == null`, navigator.dart:3807) — verified the hard way: sharing one instance crashed with `HeroControllerScope` assertion.

**Decision:** one `RouterObserver` on the `GoRouter` (covers welcome/login/event-detail/… plain routes) + one on the `ShellRoute` (covers the 5 tabs). Each navigator's pushes are reported exactly once; the null-name shell push is dropped by the name guard; the consecutive dedupe absorbs `go()`-to-same-location re-pushes.

**MISTAKE 1 (integration test design):** the first shell test asserted `sink.events == ['screen_view']` after pumping the main shell — it recorded NOTHING because the tab navigator had no observer (see above). The fix was the shell-level observer, not the test.

**MISTAKE 2 (shared observer):** initially wired ONE observer instance on both the GoRouter and the ShellRoute — the framework rejects multi-navigator attachment. Fix: two instances (the class is tiny; each holds its own service ref + dedupe state, which is what we want).

**MISTAKE 3 (test assertion):** the stub-mode flow test asserted `find.text('Iniciar sesión')` `findsOneWidget` — the login screen renders it twice (title + button). Fixed to `findsWidgets`.
