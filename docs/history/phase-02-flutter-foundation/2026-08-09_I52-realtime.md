## What was built

1. **`lib/core/providers/realtime_provider.dart` (NEW, the standard)**
   - `realtimeChannelProvider` — `StreamProvider.autoDispose.family<Map<String, dynamic>, RealtimeChannelRequest>` where `RealtimeChannelRequest = ({String channelName, String table, PostgresChangeEvent event})`. Subscribes through the realtime service; every `newRecord` of the postgres callback is emitted on the stream.
   - **ERROR handling:** `channelError`/`timedOut` (the subscribe status callback — the public seam the SDK exposes for join failures, RLS-denied postgres bindings, timeouts) surfaces as a stream error event → `AsyncError` in consumers, and schedules a re-subscribe.
   - **RECONNECTION:** exponential backoff reusing I-07's `backoffDelay` (AWS full-jitter) via an injectable `RealtimeRetryConfig` (`realtimeRetryConfigProvider`: initialDelay 1s, factor 2, maxRetries 3, seeded-Random seam for tests). Each retry creates a FRESH channel — the realtime_client SDK throws on a second `subscribe()` on one channel instance (verified in realtime_client 2.11.0 source).
   - **Dispose safety:** `ref.onDispose` cancels the pending backoff timer, unsubscribes the channel, closes the controller; the postgres callback and status path are guarded on `controller.isClosed` so a late delivery after dispose is a no-op, never a throw into the SDK callback.
   - **maxRetries exhausted** → terminal: status `error`, channel torn down, stream closed; consumers `ref.invalidate` to re-subscribe from scratch.
2. **`realtimeStatusProvider(channelName)`** — `NotifierProvider.family<RealtimeStatusNotifier, RealtimeStatus, String>` with `RealtimeStatus {connecting, connected, reconnecting, error, closed}`. Minimal design (mission: "pick minimal"): a synchronous per-channel status notifier updated by the stream provider via lazy `ref.read` — no second channel/stream needed. **Keep-alive by design** so a re-entering screen reads the last known state.
3. **`lib/core/services/realtime_service.dart`** — `_subscribeToChannel` promoted to public `subscribeToChannel(...)` with optional `onStatus` callback wired into `channel.subscribe(onStatus)` (the lifecycle seam). Existing methods unchanged in behavior; `subscribeToMessages` delegates to it (0-arg `subscribe()` preserved when `onStatus` is null → zero churn in existing tests).
4. **`test/providers/realtime_provider_test.dart` (NEW, 5 tests)** — fake `RealtimeService` (mocktail channels, captured status + postgres callbacks): newRecord delivery; onDispose unsubscribes + late-delivery no-op; dispose-mid-backoff cancels the reconnect; channelError → AsyncError then stream continues after backoff retry (fresh channel, old one unsubscribed); maxRetries exhausted → terminal error + teardown.
5. **`test/services/realtime_service_test.dart` (+2)** — `subscribeToChannel` passes the status callback into `channel.subscribe` (verified by driving the captured callback); plain subscription keeps the 0-arg `subscribe()` shape.
6. **`integration_test/realtime_flow_test.dart` (NEW, hermetic)** — a real `ConsumerWidget` watches `realtimeChannelProvider` against the fake service: loading → row rendered → channelError → error UI → backoff re-subscribe → delivery resumes. **Authoring complete + `dart analyze` clean, but could NOT be executed:** see Issues.

## Decisions

1. **Moved `lib/shared/providers/realtime_provider.dart` → `lib/core/providers/realtime_provider.dart`** (cleaner home; FILE-OWNERSHIP + the service's doc header already name the core path). The old stub was **unused** (grep: zero importers). `lib/shared/providers/` deleted (structure_test forbids empty dirs). No import updates were needed.
2. **Record-typed family argument** `RealtimeChannelRequest` (channelName, table, event) — matches the mission signature `(channelName, table, event)` with one family parameter; repo already uses records.
3. **Status via keep-alive notifier, not a second stream** — minimal per mission ("or expose via the same provider's AsyncValue; pick minimal"). Also cheaper: no duplicate channels.
4. **`subscribe()` shape preserved for plain subscriptions** — the service calls `channel.subscribe(onStatus)` only when `onStatus != null`, so I-44's pinned 0-arg mocktail stubs keep matching.
5. **Chat left as-is (mission step 4)** — `chat_screen.dart` uses `chatService.subscribeToMessages` directly with per-screen dispose (I-38's design, E2EE decryption on delivery). Rewiring would require an E2EE-aware wrapper (rows must be decrypted) — NOT trivial. **The provider is documented as the standard for new features** (notifications center, event status, QR tokens).
6. **Integration-flow registration deferred** — `integration_test/runner.sh` was lock-held by I-55 (in-flight events work); registering would have blocked. The flow file is standalone-runnable (`flutter test integration_test/realtime_flow_test.dart`) and will be registered by the orchestrator or a follow-up once I-55 releases.

## MISTAKES (searchable)

- **MISTAKE-1 (Riverpod cycle):** `ref.watch(provider.notifier)` INSIDE a provider build trips Riverpod's `_debugCurrentlyBuildingElement` assertion (`'Failed assertion: line 479 pos 11'`). Fix: resolve the notifier lazily via `ref.read` on first runtime use (status callback / timer), never during build.
- **MISTAKE-2 (family notifier base class):** `NotifierProvider.autoDispose.family` requires `AutoDisposeFamilyNotifier<State, Arg>`; `NotifierProvider.family` requires `FamilyNotifier<State, Arg>` — plain `Notifier` fails the bound. (Repo pattern: `FamilyAsyncNotifier`.)
- **MISTAKE-3 (no hoisting):** Dart does NOT hoist local function declarations — a closure referencing a function declared later fails ("can't be referenced before it is declared"), including mutual references between `connect`/`onChannelError`. Fix: `late void Function()` closures assigned before use.
- **MISTAKE-4 (mocktail enum):** `when(... event: any(named: 'event'))` on a `PostgresChangeEvent` param throws at registration without `registerFallbackValue` — using concrete captured values avoids it entirely.
- **MISTAKE-5 (fake fidelity):** the first fake service registered a `when(onPostgresChanges)` stub but never INVOKED `channel.onPostgresChanges` like the real service does → the capture never ran (`onPostgresCallback` null). Fix: mirror the service wiring in the fake.
- **MISTAKE-6 (test listener):** `AsyncValue.hasValue` is TRUE on `AsyncError` (it preserves prior data) — collecting "rows" via `hasValue` duplicated the last row on the error event. Fix: collect only `next is AsyncData`.
