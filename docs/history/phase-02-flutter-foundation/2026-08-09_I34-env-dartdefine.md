## Research (sources)

- `flutter build apk -h` (Flutter 3.44.1, this machine): `--dart-define-from-file=<json|.env>`
  supported; **"Entries from `--dart-define` with identical keys take precedence over entries
  from these files"** — so CI can always override the dev `.env` file.
- `String.fromEnvironment` is a `const` constructor — values bake in at compile time
  (`defaultValue` applies when the define is absent); impossible to read in unit tests
  without a define, hence the pure `EnvConfig.validate` seam.
- The repo already models this pattern in `integration_test/support/test_users.dart`
  (dart-define consts) and the old Juega reference (`--dart-define=SUPABASE_URL="$$SUPABASE_URL"`).

## Decisions made and why

1. **`validate` public (not `_validate`)** — Dart private members are library-private; a test
   in another library cannot call `EnvConfig._validate`. Public pure seam = unit-testable
   missing-var behavior without compile-time defines. Documented on the method.
2. **`.env.example` URL → `http://127.0.0.1:54386`** — the old value was the real prod domain
   (qallariy.lat), violating the "deployment URLs are placeholders" directive; §2.1 names the
   local dev URL as the canonical example. Structure/keys unchanged.
3. **Key rotation NOT performed** — rotation of the exposed anon key happens in the Supabase
   dashboard (human/ops action, R12 in DEPLOYMENT-PLACEHOLDER; M-13/S-08 at release). The
   repo side is placeholder-only now. Flagged in SEC-03 status.
4. **Makefile kept minimal on purpose** — M-13 owns the full env-sourcing pass; this lands
   only the working dart-define seam (`FLUTTER_DEFINES` + `define-env` + build/dev wiring) so
   the app compiles with defines today and CI has a documented override hook.
5. **Test/analyze targets left untouched** — dart-define is not needed there (env tests
   explicitly assert the ''-default behavior); M-13 can extend later.
6. **`flutter_dotenv` moved to the dead-dep guard loop** in `pubspec_test.dart` so a re-add
   fails CI (SEC-09 regression guard), mirroring the I-23 dead-dep pattern.

- **`--dart-define-from-file` caveats for M-13** (from the CLI help + research):
  - Supports `.env` and JSON; keys are taken literally — no shell expansion (`$VAR` refs),
    no value substitution, no per-key filtering. Empty values in `.env` define empty strings
    (harmless for the app's two keys).
  - `--dart-define` **wins** over `--dart-define-from-file` on identical keys (verified in
    `flutter build apk -h`) — recommended CI pattern.
  - `make install TARGET=ios` runs `make build` **on macvm over SSH** — that host needs its
    own `.env` (or explicit `FLUTTER_DEFINES=…` passed through) or the build fails fast.
  - Quote handling: values with spaces/quotes are taken literally in .env files — keep the
    file quote-free (it already is).
- **`test/services/secure_session_storage_test.dart`** has a pre-existing unused import
  (analyze warning) — not mine, I-47 scope.
