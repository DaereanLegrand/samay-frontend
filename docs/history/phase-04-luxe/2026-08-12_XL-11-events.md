## Decisions

- **Detail hero owns the title.** AppBar on the data state is title-less
  (back only); the name renders once, UPPERCASE, as the peach VDisplayText
  hero (loading/error scaffolds keep the `eventDetailTitle` AppBar — no hero
  exists there, so no duplicate).
- **One peach accent chip family, not five.** Only the *type* chips get
  `VChip.accent(peach)` (they drive the form); visibility/join/remainder stay
  neutral white chips. 60-30-10 accent scarcity (ColorUxLab, below) — the
  peach family is the CTA/badges/hero's job.
- **Status color semantics yield to the family directive.** The old status
  badge was white-fill (live) / pink-fill (cancelled) / gray (ended/draft).
  All now render `VBadge.accent(peach)`; the state rides on the label alone —
  the design doc's own rule 5 ("color is never the only signal", ESTA §1)
  and Mobbin's badge guidance (below). Flagged for the Gemma critique round
  (XL-18) as the one deliberate semantic regression the directive orders.
- **Chip "gradient border" resolved via `VChip.accent`.** VChip's accent
  contract renders the family border + vivid fill when selected ("pass
  `gradient:` to adopt another family") — that is the sanctioned LUXE
  selection chip; composing a `VGradientBorder` ring around a chip would
  fork the shared component. Documented for Gemma review.
- **Underline date rows / group selector kept.** The mandate says the form
  rows are already glass and untouched; the two `InputDecorator`-underline
  rows contradict LUXE directive #7 but are left alone (flagged for XL-18 —
  a `VGlass`-wrapped picker row would be the fix).
- **Glow discipline:** one `glowAccent` CTA per screen, hero glow from
  VDisplayText, card glows at the VGlassCard default 0.18, aurora at α0.08
  ("faint"). No new tokens were needed — only existing `AppGradients.peach`
  / `AppColors` / `AppTypography.sectionLabel` references.

## MISTAKE blocks

- **MISTAKE (scope):** `dart format lib/features/events/` reflowed the
  READ-ONLY `logic/event_form_data.dart` + `providers/events_providers.dart`
  into the new tall formatter style (63 diff lines, all whitespace). Caught
  in the diff review and restored via `git checkout` after verifying the diff
  was formatting-only. Lesson: format the owned files only, never the whole
  feature dir.
- **MISTAKE (test infra):** two tests asserting snackbars broke after the
  restyle. Cause: `pumpAndSettle` keeps pumping while the VAurora drift
  animates (~10s of scheduled frames), which fires the snackbar's 4s
  auto-dismiss timer mid-settle — by the time settle returns, the snackbar
  is gone. Fix: explicit short pumps (`pump()` + `pump(300–500ms)`) at the
  two snackbar-asserting spots instead of `pumpAndSettle`.
- **MISTAKE (layout):** the detail 'editar navigates' test tapped 'Editar'
  without scrolling — it only worked because the pre-LUXE layout barely fit
  the 600px viewport. The glass cards grew the page, pushing the buttons
  below the fold. Fix: drag −400 before the tap (same pattern as the other
  detail tests).

## Sources (web research, 2026-08-12)

- **Badge discipline:** "Badge UI Design: Best practices, Design variants &
  Examples" (Mobbin, fetched live) — badges are non-interactive status
  carriers; "avoid adding badges to every element; it can overwhelm users
  and reduce their impact" → the events detail shows exactly 2–3 badges and
  every badge carries its state in the label;
  https://mobbin.com/glossary/badge
- **Accent scarcity / glass:** "Mobile App Color Design: Guide for iOS &
  Android" (ColorUxLab, fetched live) — the 60-30-10 rule (accents are 10%),
  glassmorphism "requires strong text and icon contrast", semantic colors
  must never be the only signal, iOS expects "subtle translucency and depth"
  → the single glowAccent CTA + VGlassCard meta cards + peach-family badges;
  https://coloruxlab.com/guides/mobile-app-color-design
- **Reduce-motion discipline:** "prefers-reduced-motion: Sometimes less
  movement is more" (web.dev, fetched live) — decorative animation must be
  removable; motion-triggered vestibular disorders make reduced motion a
  medical necessity → VAurora/VDisplayText static fallbacks honored (no
  new work needed, verified the widgets' disableAnimationsOf paths);
  https://web.dev/articles/prefers-reduced-motion
- **Secondary (re-cited from the XL-14 sweep log, verified same day):**
  "Mastering Gradient Design" (DesignRush, 2025-05-14) — contrast-first on
  gradient surfaces; "Best 8 Mobile App Color Scheme Trends for 2026"
  (Envato Elements, 2026-02-24) — dark mode + soft-tech pastels; "Is it good
  to mix filled and outline badges?" (UX Stack Exchange) — one styling per
  theme.
- Attempted "2026 event creation UI", "luxury event detail design" and
  "peach pastel dark UI" searches: DuckDuckGo bot-blocked, Bing returned
  unrelated results, and several 2025-era article URLs from the XL-14 log
  have since 404'd (DesignRush trends page 403, onething/eleken/softs/
  gendesigns/uxmatters 404). The three live sources above + the XL-14 log's
  verified citations cover the design decisions made.
