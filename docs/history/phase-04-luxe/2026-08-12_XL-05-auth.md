## What was built

All 9 auth screens restyled to the LUXE v2 language (rendering-only; routes,
providers, flows, l10n keys byte-identical). Every screen now resolves its
gradient family via `AppGradients.familyOf` (NO pink mains — 2026-08-12

## Decisions

- **Family resolution is data-driven** — every screen calls
  `AppGradients.familyOf('<screen-key>')` once and threads the result into
  the aurora, hero and CTA. Zero hardcoded families; the ORCHESTRATION map
  stays the single source of truth (XL-01's exact map).
- **Welcome brand moment = violet hero + violet/cyan dual aurora.** The
  wordmark is violet (`VDisplayText` 64 = `displayLarge`); the dual-family
  wash lives in the aurora (`[violet, cyan]`) so "violet→cyan dual" reads
  ambient, not in the glyphs.
- **Signup hero** — "Crea tu cuenta" keeps the Playfair voice but now renders
  the violet multi-color gradient with the slowly pulsing glow via
  `VDisplayText` — NOT pink (user directive).
- **One hero per screen, one CTA per screen.** AppBar titles dropped where
  they duplicated the hero (signup/otp/age_gate/privacy_terms/profile_setup/
  forgot_password/login). Screens without a hero before (login,
  profile_setup) gained the hero instead of the AppBar title.
- **CTA doctrine:** `glowAccent` (filled, family gradient, black text) for
  the 3 "leave the funnel" actions (welcome create, login sign-in, otp
  verify, forgot send); `emphasized(gradient:)` for in-funnel continues
  (signup, age_gate, privacy_terms, profile_setup). Exactly one glowing CTA
  per screen.
- **Test updates were case/pump-only.** `VDisplayText` enforces MAYUS
  (directive #6), so exact-string finders moved to the uppercase glyph:
  `'Crea tu cuenta'`→`'CREA TU CUENTA'`, `'Revisa tu correo'`→
  `'REVISA TU CORREO'`, `'Cuenta suspendida'`→`'CUENTA SUSPENDIDA'`, etc.
  The pink-assertion failures XL-14 reported (welcome + forgot glowAccent)
  now assert the family gradient + black text (`_expectFilledGlowAccent`).

## MISTAKE blocks

- **MISTAKE (label drift):** first draft of `login_screen.dart` added
  `l10n.welcomeTagline` as a login subtitle — a label change violating
  "same labels". Caught in review, removed; l10n keys are untouched.
- **MISTAKE (test compile):** `_expectDisplayHeader` used `tester` without a
  parameter → 2 analyzer errors. Fixed by threading `WidgetTester` in.
- **MISTAKE (snackbar timing):** the forgot-password "email → send →
  confirmation" test asserted the F7 snackbar after `pumpAndSettle` — the
  aurora drift (10s cycle) now keeps settle pumping past the snackbar's 4s
  auto-dismiss, so the snackbar was gone on assertion. Fixed with two
  deterministic pumps (`pump()` + `pump(300ms)`). Documented in the test.
- **MISTAKE (test relied on removed chrome):** `auth_screens_test` signup
  test found 'Crear cuenta' via the deleted AppBar title; added the
  `pumpAndSettle` the sibling login test already used (provider settle →
  CTA label renders).
