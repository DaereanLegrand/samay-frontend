## Decisions

1. **Aurora α0.06 on every profile screen.** The brief's floor: "profile is
   informational, keep the aurora faint". All five screens use
   `VAurora(gradients: [AppGradients.gold], opacity: 0.06)` — a single gold
   family, no multi-color ambient (the multi-family default is for
   non-family screens).
2. **Hero size 28 (headlineLarge metrics), not 40.** The username is the
   §3.2 fancy moment, not a welcome wordmark; `VDisplayText(size: 28)`
   maps to the existing role metrics.
3. **Public-profile AppBar title removed.** The loaded AppBar showed
   '@dana' while the body rendered the hero 'DANA' + handle '@dana' —
   directive #8 ("no title duplicated in AppBar + hero") bans exactly this.
   The overflow menu keeps its action slot. Fallback hero still shows
   `commonUser` (now uppercased by the MAYUS rule).
4. **Delete CTA wears the gold ring, not error pink.** LUXE: the screen owns
   gold; danger stays in the semantic error *inside* the flow (dialog,
   settings rows). The CTA is disabled until the email matches, so the ring
   is a family accent, not a danger signal. Documented in code.
5. **Balance card + settings groups get a transparent `Material` inside the
   glass** so `InkWell`/`ListTile` ink splashes paint above the glass face
   (the VCard precedent from U-15 R6; the framework asserts otherwise).
6. **Danger semantics untouched** (`AppColors.error` = glowPink 6.00:1 AA) —
   the ORCHESTRATION-LUXE documented exception; the settings danger pair,
   both confirm dialogs and the delete-CTA disabled state keep it.
7. **No new tokens.** Gold family + sectionLabel + VGlassCard/VDisplayText/
   VAurora all landed by XL-01..XL-04/XL-14; nothing needed adding to
   `app_colors.dart`/`app_gradients.dart`.

## MISTAKE blocks

- **MISTAKE-1 (test semantics, the big one):** after adding the VAurora
  wrap, four previously-green snackbar tests failed — avatar_flow ×3
  (rationale / avatar-updated / server-error snackbars) and
  delete_account_flow ×1 (email-mismatch snackbar). Root cause:
  `pumpAndSettle` advances the fake clock until no frames are scheduled;
  the aurora's 10s drift keeps frames scheduled for ~10.3s, and the
  snackbar's 4s auto-dismiss timer fires mid-settle — by settle time the
  snackbar is gone. **Fix:** replace the post-tap `pumpAndSettle()` with
  bounded pumps — `pump()` (flush the all-microtask async chain — verified
  the fake Supabase HTTP layer is timer-free) + `pump(400ms)` (snackbar
  entrance, 250ms, complete; 4s dismiss not reached). No test asserts after
  a settle anymore on snackbar flows.
- **MISTAKE-2 (format churn):** ran `dart format` over the whole
  `lib/features/profile/` + `test/features/profile/` — the repo baseline is
  NOT formatter-canonical in places (older hand-edits), so four files I
  don't own (interests_test, providers/profile_providers, interests widget,
  and most of avatar_flow_test) absorbed pure normalization churn. **Fix:**
  `git checkout`-reverted the three files I made no intentional edits to and
  re-applied avatar_flow's three bounded-pump edits by hand. Final diff is
  exactly the intended edits + my own files' normalization.
- **MISTAKE-3 (mid-flight interference):** while testing, the 4-file run
  reported 4 "loading" failures — traced to a transient syntax error in
  `lib/features/groups/screens/my_groups_screen.dart` (XL-10's in-flight
  edit; later `invite_screen.dart` blocked app_router_test the same way).
  Re-ran each suite individually after the other agent's edit landed —
  all green. Not mine, reported below.
