## Web research (cited)

1. **Liquid glass** — Apple HIG, *Adopting Liquid Glass*
   (developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass):
   translucency + fluid morphing animations, and the OS "reduce motion /
   reduce transparency" accessibility preferences must be honored. Also
   "reserve glass for the floating navigation layer, avoid full-screen
   backgrounds" → the aurora stays behind content and glass stays minimal
   (restraint is a campaign non-negotiable).
2. **Aurora UI** — superdesign.dev/styles/aurora: "layered radial gradients
   blurred together over a near-black base", purple/teal/pink, drifting
   blobs; static needs ~4 layers + blur. → Samay uses 3 blobs at α0.04–0.10
   over the always-black background.
3. **Aurora drift** — animationpatterns.art/animations/aurora-gradient-sweep:
   "layered radial-gradient blobs, transform-only drift, blur, opacity, and
   reduced-motion handling" → drift is transform-only (cheap), reduced-motion
   freezes positions (implemented).
4. **Reduced motion** — web.dev/articles/prefers-reduced-motion (Thomas
   Steiner): decorative animation is a medical necessity to remove for
   vestibular-spectrum users → all three widgets static + ticker-free under
   `MediaQuery.disableAnimationsOf`.
5. **flutter_animate 4.5.2** (pub.dev/packages/flutter_animate, gskinner,
   verified publisher, Flutter Favorite): legit, but its README's own loop
   idiom is `controller.repeat(reverse: true)` — the exact hard-repeat
   pattern that hangs `pumpAndSettle` (documented in `VBreathingGlow`), and
   its testing docs offer no idle-safe settle. The repo already owns the
   deterministic engine; adding a dependency for 3 small widgets was rejected.
   **DECISION: custom AnimationControllers, mirroring the repo engine.**

## Decisions

- **Idle-safe engine everywhere** (settle-rest + periodic restart +
  `isAnimating` guard): identical skeleton to `VBreathingGlow` — reduces
  divergence across the campaign and keeps every `pumpAndSettle` test
  deterministic.
- **`TickerFuture.then` timing** (see MISTAKE 2): the reverse leg's clock
  starts at its first tick (one frame after the up leg completes) — tests
  pin the down leg with two pumps.
- **Reduced-motion static values**: glow α0.55 (spec), dots α1.0 (spec),
  aurora base positions (value 0).
- **`AppGradient.radial()`** consumed exactly per the XL-01 contract; blob
  fill rebuilt explicitly (center/radius/colors/stops) because
  `RadialGradient.copyWith` doesn't exist in this Flutter.
- **Durations**: all five tokens added verbatim from the brief; existing
  tokens untouched. `glassHover == fast` (150ms) is intentional — semantic
  role token for the glass hover micro-interaction (XL-03 will consume it).
- No new colors/hex — only tokens (`withValues` alphas on existing colors),
  passing the conventions guards (`Colors.*` / `Color(0x…)` absent).

## MISTAKE blocks

### MISTAKE 1 — `AnimationController(curve:)` doesn't exist here
`AnimationController(vsync:…, curve: Curves.easeInOut)` — this Flutter
(3.44.1) removed the constructor curve param AND the `curve` property.
Fix: `Curves.easeInOut.transform(_controller.value)` in build. Verified the
transform is exact at 0 / 0.5 / 1.0 (bezier symmetry), so the deterministic
test points hold. (Fixed before first green run; caught by the compiler.)

### MISTAKE 2 — down-leg test pinned one frame too early
Test asserted α0.35 right after a single `pump(glowPulse ~/ 2)` post-peak.
`TickerFuture.then` runs in the post-frame microtask, so `reverse()`'s first
tick — which sets its clock — lands on the NEXT frame; the value had only
just started descending (probe: t=3800 → α0.352, t=3900 → α0.35). The engine
is correct (the repo's `VBreathingGlow` tests never pinned the down leg;
`pumpAndSettle` covers it). Fix: pump the down leg in two halves. Documented
here so future agents don't "fix" the engine.

### MISTAKE 3 — `RadialGradient.copyWith` doesn't exist
Attempted `gradient.radial().copyWith(colors: …)` to water the blob alpha —
no such method on `RadialGradient` in this Flutter. Fix: build the
`RadialGradient` explicitly from `base.center/radius/colors/stops`.
