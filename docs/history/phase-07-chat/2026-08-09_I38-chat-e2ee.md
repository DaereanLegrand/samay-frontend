## Decisions & deviations (S-07 audit inputs)

- **Consolidated prekey storage vs E2EE-ARCHITECTURE §9.1** (documented in the migration header): one `e2ee_identity_keys` row instead of `user_devices`/`signed_prekeys`/`one_time_prekeys` tables; OPKs consumed into a `consumed_one_time_prekeys` jsonb marker (mission spec).
- **Two columns added vs the mission's column list** (crypto-core requires them): `identity_sig_key` (Ed25519 public — X3DH sig verify + AD_base) and `signed_prekey_id` (init envelope carries spk_id; responder must load the matching private key). Both documented in the migration.
- **Rate limiting (§5.5) deferred** to S-10 — `FOR UPDATE SKIP LOCKED` already serializes OPK consumption; the fetch-log counter needs a log table + caller identity (noted in the migration).
- **Own-message display:** the sender cannot decrypt its own envelopes with the peer-bound session; an in-memory outbox shows sent messages; after an app restart own history renders as the undecryptable placeholder (E2EE §8.4: plaintext never persisted — documented MVP limitation).
- **Re-decrypt safety:** decrypted history is cached in memory and decrypts are serialized per chat (the ratchet session is stateful; concurrent or replayed decrypts would fail AEAD and mark good messages).
- **Auth lifecycle hooks (§12.2 step 4: publish at profile creation, wipeAll on sign-out)** are NOT wired — send-time lazy publish (`handleMissingSession`) covers the send path; the hooks are a documented follow-up (auth_provider is I-09/I-47 territory).
