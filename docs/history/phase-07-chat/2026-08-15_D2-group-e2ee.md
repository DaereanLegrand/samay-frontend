## What was built

Signal sender-key ("sender-key message") model for E2EE group chat, parallel
to D1-groupchat-db (server) and the future service/UI agents:

- `lib/crypto/envelope.dart` — **type 0x03** sender-key envelope: fixed 62-byte
  header `magic(4) ‖ version(1) ‖ type(1) ‖ sender_ik_dh(32) ‖ group_id(16) ‖
  chain_index(4) ‖ ct_len(4)` + ciphertext. `SamayEnvelope.senderKey(...)`
  factory, `senderKeyHeaderSize`, `encode()`/`tryParse()` extended; 0x01/0x02
  untouched. `groupIdToBytes`/`groupIdFromBytes` UUID↔16-bytes helpers.
- `lib/crypto/constants.dart` — `e2eeEnvelopeTypeSenderKey` (0x03),
  `e2eeEnvelopeGroupIdLength`, `e2eeSenderKeyBundleVersion` (1),
  `e2eeSenderKeyBundleKind` (`samay.group_sender_key`),
  `e2eeSenderKeyRecordVersion`/`e2eeSenderKeyRegistryVersion` (1).
- `lib/crypto/group_cipher.dart` (new) — `GroupE2eeCipher` +
  `GroupSenderKeyRecord`: chain creation (32 random bytes, `Random.secure()`),
  `deriveMessageKey` chain walk, AEAD with `aad = utf8(groupChatId) ‖ groupId`,
  bundle distribution JSON, strict in-order replay handling (`n <= lastSeenN`
  → drop), identity binding (envelope `sender_ik_dh` vs stored bundle `ik_dh`),
  own-bundle/own-echo protection, `wipeGroupKeys` rekey, per-device
  `membersMissingSenderKey`.
- `test/crypto/group_cipher_test.dart` (new, 34 tests) +
  `test/crypto/envelope_test.dart` (0x03 group, 6 tests; the old
  "unknown type" test now uses 0x04).

## Decisions

- **Storage namespace** (recorded in the class doc, §8.2 family): records live
  in the session store under `group_sender_key:<groupId>:<senderUserId>`
  (effective secure-storage key `samay.e2ee.session.group_sender_key:...` —
  the store prepends its own prefix). A per-chat **registry**
  `group_sender_key_registry:<groupChatId>` = `{group_id, senders[]}` bridges
  the chat layer's `chat_id` to the crypto `group_id` and is the enumeration
  source for `wipeGroupKeys` (E2eeSessionStore has no key-listing method; the
  registry is written AFTER the record so a crash orphans a record the member
  re-distributes, never strands a member without a chain — documented choice).
- **Chain indexing:** bundle carries `chain_index: 0`; first message = index 0;
  receivers store `lastSeenN = chain_index - 1`; gaps derive through and
  discard skipped keys; `n <= lastSeenN` → silent drop. Own sent history is
  never decryptable (one-way chain, forward secrecy).
- **membersMissingSenderKey** is per-device (stores are per-device): it
  excludes members whose records THIS device holds. The chat layer calls it on
  the local cipher before each distribution round.
- **AAD** binds both the chat (`groupChatId`) and the crypto group
  (`groupId` bytes) — header-groupId tampering fails AEAD (cross-group replay
  test), header-groupId swap to a foreign namespace is a silent drop.

## MISTAKE-1

Test semantics for `membersMissingSenderKey` initially assumed cross-device
knowledge ("bob processed ⇒ alice's query excludes bob"). Impossible with
per-device stores; corrected to "members whose records this device holds".
Watch for this when the service agent wires distribution: the chat layer must
re-query on the member's own device.
