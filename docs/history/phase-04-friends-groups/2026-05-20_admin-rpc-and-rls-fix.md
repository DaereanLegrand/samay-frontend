# Phase 04 — Admin RPC & RLS Fix (Post-Audit)

## Date: 2026-05-20

## Commits

## Overview
Post-audit fix: the Go CLI called RPCs (`grant_shards`, `grant_preshards`, `distribute_shards`, `recalculate_ranks`) that did not exist in the database. Also, the `users_search` RLS policy was too permissive — it exposed all user columns to any authenticated user. This fixes both.

---

## What was built

### Migration: `20260520000001_admin_rpc_and_rls.sql` (224 lines)

#### SECURITY DEFINER RPCs (4)

| Function | Purpose | Called by |
|----------|---------|-----------|
| `grant_shards(p_user_id, p_amount, p_reason)` | Adds personal shards, records in `shard_ledger` | CLI `users grant-shards` |
| `grant_preshards(p_user_id, p_amount, p_reason)` | Adds preshards, records in `preshard_ledger` | CLI `users grant-preshards` |
| `distribute_shards(p_event_id)` | Full preshard distribution: zero-attendees full return, per-user cap, remainder action, ledger entries. Idempotent. Returns JSON result. | CLI `events distribute-shards` |
| `recalculate_ranks(p_tier)` | Percentile-based rank recalculation for a tier (or all tiers). Assigns `rank_bracket`, writes `group_rank_snapshots`, prunes snapshots >30 days old. | CLI `shards recalculate-ranks` |

#### RLS tightening: `user_search_view`

- Dropped overly permissive `users_search` policy (exposed all columns)
- Created `user_search_view` — a `security_barrier` view exposing only `id, username, avatar_url` for non-deleted users
- Granted SELECT on the view to `authenticated` and `anon`

---

## Decisions Made
- **SECURITY DEFINER is necessary here**: The CLI connects with `service_role` key. For `grant_shards`/`grant_preshards`, we can't rely on client-side writes because they need to atomically update shard balance + ledger. For `distribute_shards`/`recalculate_ranks`, the logic is too complex for a single PostgREST call.
- **user_search_view over column-level RLS**: A security barrier view is simpler than column-level grants. It also prevents the Flutter app from accidentally requesting columns it shouldn't see.

## MISTAKEs
1. The `display_name` column was dropped in migration `20260512000010` but the Go code was never updated. The CLI would silently fail or return empty columns on select queries.
2. The `users_search` RLS policy was too broad from day one — it allowed reading every column of every user. The spec only requires `id, username, avatar_url` for search. Fixed with `user_search_view`.
