## Decisions

- **Add the `create_minigame_session` RPC** (mission's DECIDE point): it
  closes the escrow gap cleanly for session creation. Direct inserts were
  impossible anyway — `minigame_sessions` has no INSERT/UPDATE policy under
  FORCE RLS and `users.personal_shards` is column-REVOKEd from
  authenticated (G-03); only a SECURITY DEFINER RPC can do the atomic
  deduct+ledger+insert.
- **jsonb statuses, not RAISE** for business outcomes (I-57 pattern): the
  provider maps `MinigameSessionRejection.notMember` / `.insufficientShards`
  / `.invalidGameType` to friendly localized snackbars without string
  sniffing (which would also trip the I-15 extraction guard).
- **join/updateStatus stay client-side contracts with a documented server
  RPC gap**: `minigame_sessions` UPDATE is RLS-blocked, so `joinSession` and
  `updateStatus` cannot succeed against the live DB until
  `join_minigame_session` + `finish_minigame_session` SECURITY DEFINER RPCs
  land (see MISTAKE/gaps). The create path (the foundation's main flow) is
  fully server-backed.
- **Session status via the I-52 `realtimeChannelProvider`** (the documented
  standard for new realtime features), merged into a family notifier —
  avoids a second service-level subscription path while keeping
  `MinigameService.subscribeToSession` as the channel handle (service
  contract parity with `subscribeToNotifications`).
- **Route `/minigames/:groupId`** (not a group-detail tab): GMCR's "Juegos
  tab" entry point is a small follow-up; FILE-OWNERSHIP keeps
  `group_detail_screen.dart` with other agents (U-11/GMCR follow-up).

## MISTAKE blocks

- **MISTAKE (test-only):** mocktail `select()` stubs must match the
  `select(columns)` argument — `when(() => table.select())` silently
  returns null for `select(_columns)`, producing confusing
  Null-not-subtype failures; register `select(any())`.
- **MISTAKE (test-only):** `ResolvingBuilder<PostgrestList>(null)` fails the
  `as List<Map>` cast when the builder is awaited directly — use
  `ResolvingBuilder<PostgrestList>(<Map<String, dynamic>>[])` for empty
  results; `maybeSingle`-style nulls need the nullable transform type.
- **MISTAKE (integration):** a 360px-logical phone viewport only builds the
  first two cards of the horizontal picker — the flow test must drag the
  picker before tapping the 3rd game, and scroll the sessions list before
  asserting below-the-fold session cards.
- **MISTAKE (UI):** the session status `VChip` (FilterChip) swallows the
  pointer in its own hit test — widget tests tap the card's wager subtitle
  instead of the chip.

## Open gaps (flagged, do-not-fix)

- **Winner settlement RPC gap (I-77/S-03 handoff):** `minigame_win` ledger +
  escrow credit and `minigame_refund` on draw are NOT implemented — GWAG
  §Wager Resolution needs a SECURITY DEFINER `finish_minigame_session`
  RPC (also unblocks `updateStatus`'s RLS block). Until then, wagered
  escrow can only be created, never resolved via the client.
- **`join_minigame_session` RPC missing:** `joinSession` (client contract,
  tested) is RLS-blocked server-side.
- **Per-game UIs are future work** (documented): poke timers, hot-seat
  turns, Verdad/Reto pools, bottle spin, challenge timeouts + votes —
  the hub's detail placeholder snackbar is the intended seam.
- **Entry point:** group detail has no "Juegos" nav yet (GMCR game-list-in-
  group-detail; keep `group_detail_screen.dart` ownership clear).
- **Realtime publication:** `minigame_sessions` is NOT yet in the
  `supabase_realtime` publication — row changes won't stream until a small
  migration adds it (S-11/I-77; the client stack is ready).
